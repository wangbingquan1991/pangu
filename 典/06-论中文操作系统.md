# 论中文操作系统

## ——以「盘古开天」工程为例：从与非门到以中文与易学为命名本源的计算体系

> 撰于 2026-08-31。本文所引数据全部出自本仓库实测与 `典/` 各规范文档，无一凭记忆杜撰。

---

## 摘要

「中文操作系统」长久以来被两种想象裹挟：一是把界面字符串翻译成汉字的「表面汉化」，二是认为中文天然不适合系统级编程的「拼音文字中心论」。本文提出第三条路线并给出实证：**操作系统的「中文性」不在于界面语言，而在于命名体系**——计算栈自下而上的每一层，本质都是对下一层的一次命名；将这套命名以中文与易学重建，即得一个血统为中文的操作系统，而其底层电路与全世界的机器并无不同。

「盘古开天」工程自 2026-08-30 立项，自逻辑门起、自底向上重建计算体系。截至本文写作时，已完成三个里程碑：门级模拟器（M0）、二十四位算术运算器（M1）、时序电路与存储器并跑通取指之机（M2），全量 31 项测试全绿，总规模近万门，全部由与非门派生。本文论述其理论基础、体系设计、工程阶段、开发过程与方法论，并诚实讨论「中文」在计算栈各层中何处是事实、何处是记法。

**关键词**：中文编程；操作系统；易学；八卦；八进制；与非门；事件驱动模拟；命名体系

## 一、引言：问题与定位

### 1.1 两种流行想象的破产

关于「中文操作系统」，公共讨论长期停留在两端：

| 想象 | 内容 | 为何不成立 |
|---|---|---|
| 表面汉化 | 把菜单、报错、文档翻译成中文 | 这只是「本地化」，任何系统的语言包都能做到，与系统的血统无关 |
| 拼音文字中心论 | 认为系统级编程必须用英文标识符 | 混淆了「工具链的默认约定」与「语言的本质能力」——C 之后的现代语言（Rust、Go、Swift）标识符规范普遍基于 Unicode |

二者共同的盲区是：**从未有人追问「操作系统」本身由什么构成**。剥开内核、驱动、调度器这些名字，一个操作系统是「一堆约定」的集合——指令集是约定，系统调用是约定，进程是约定，文件是约定。**约定用什么语言书写，系统的血统就是什么语言。**

### 1.2 盘古开天的定位

本工程的目标**不是造一个能替代 Linux 的系统**，而是：

> 自与非门起，自底向上重建一整套以中文与易学为命名本源的计算体系，
> 产出是一台自洽可运行的计算机 + 一个能跑的操作系统 + 一条完整工具链。
> **过程本身就是成果。**

这一定位包含了明确的自我克制：不与七十年的二进制产业生态竞争，不在物理层标新立异，把全部创造性投在**命名与概念体系**这一真正无人做过、且电路无法抄袭的层面。

### 1.3 命名总纲

| 名称 | 所指 |
|---|---|
| 盘古开天 | 计划名 |
| 盘古 | 仓库根名 |

## 二、理论基础：四条不可逾越的事实边界

任何「中文计算机」设想，都必须先过以下四关。它们不是设计偏好，是已核实的硬事实，**决定了整个架构**。

### 2.1 八进制不需要「模拟」，它就是二进制

三 bit 恰为一个八进制位，无损可逆，只是分组记法。历史上 DEC PDP-8（12 位字）、PDP-11 的机器码文档都以八进制书写。八卦 = 3 bit 在数学上精确成立，**不是比喻**。

真正的约束在别处：现代通用机的字长（8/16/32/64）都不是 3 的倍数，所以八进制在那些机器上只作为**书写记法**存在，不构成硬件事实。爻机取 24 位字长，正是要让八进制从记法升格为**结构事实**——每一个 24 位字，自左至右恰好是八个卦。

顺带交代一个更深的背景：纯以信息论论，进制基数 r 的「基数经济性」在 r = e ≈ 2.718 处最优，最接近的整数是 3（苏联 Сетунь 即平衡三进制机）。但三值逻辑在噪声容限上远逊二值，故本工程恪守二进制底座，仅将《太玄》三进制符号（U+1D300 段，3⁴ = 81 tetragram）列为独立实验，**不进主运算路径**。

### 2.2 Unicode 的事实边界：卦符号不是汉字

这是全部理论中**最要紧的一条**：

| 符号段 | 码位 | Unicode 类别 | 能否作标识符 |
|---|---|---|---|
| 六十四卦 | U+4DC0–U+4DFF | **So**（Symbol, other） | ❌ 不满足 XID_Start，Rust/Go 皆拒 |
| 八卦 | U+2630–U+2637 | So | ❌ |
| 两仪、四象 | U+268A–U+268F | So | ❌ |
| 汉字 | U+4E00–U+9FFF 等 | **Lo**（Letter, other） | ✅ |

后果：**卦符号只能做汇编助记符、字面量与输出；标识符必须用汉字。** 任何声称「用 ䷀ 当变量名」的方案，在现有编译器上第一步就走不通。

另两条同类事实：

- **甲骨文未进 Unicode**：仅在第三平面（TIP）路线图被提及，2003 至 2019 五次提案均未通过。甲骨文无法用于任何文本层；强行占用私用区（U+E000 起）意味着字体、输入法、工具链全线断裂，已被明确放弃。
- **《皇极经世》的元会运世是 12/30 混合进制**（1 元 = 12 会 = 30 运 = 12 世 = 30 年），与二进制不可对齐，故只用于纪年与版本显示层，**禁止进内核数据结构**。

### 2.3 Go 语言的三条硬约束（实测）

本工程以 Go 为实现语言（选型理由：作者最熟练、并发与性能足够、模拟器/汇编器/编译器皆可承载）。Go 对中文标识符的支持经实测有三条铁律：

1. **汉字标识符一律不可导出。** Go 以首字符是否为 Unicode Lu 类（大写字母）决定导出；汉字属 Lo 类，故 `func 造()` 在包外永不可见。**⇒ 全中文必然是单一 Go 包**（`package 盘古`），源文件平铺仓库根，分层靠文件名与分节注释，不靠目录。
2. **导入路径的目录名不得含非 ASCII。** `pangu/cmd/演武` 报 `invalid char '演'`。⇒ 需被 import 的目录用 ASCII 名（`cmd/pangu/`）；纯文档目录（`典/`）可用中文名。
3. **测试函数必须带 ASCII 的 `Test` 前缀**才能被 `go test` 发现，写作 `Test译门`。

于是全系统非中文标识符只剩三处：`go.mod` 的 `pangu`、`出口.go` 的 `Run()`、测试的 `Test` 前缀。**「全中文」达成了，代价是单包——这是语言规则逼出来的唯一解。**

### 2.4 核心命题：命名即抽象

以上事实收拢为一个论点：**计算栈的每一层，都在对下一层做同一件事——命名。**

电压命名成「爻」，爻的排列命名成「卦」，卦命名成「指令」，指令打包命名成「叩」，叩的服务对象命名成「化」……命名即抽象，抽象即系统。由此推出本文的中心结论：

> 盘古与 Linux 的区别，根本不在底层电路——全世界的与非门都是同一种与非门。区别在命名体系。电路可以抄，**名字抄不了**。这正是「中文操作系统」这个命题成立、且只能这样成立的地方。

## 三、体系设计

### 3.1 命名体系（中文血统总表）

| 层 | 中文名 | 对应 |
|---|---|---|
| 信号 | 阳 ⚊ / 阴 ⚋ | 1 / 0 |
| 最小单位 | 爻 | bit |
| 2 bit | 四象 ⚌⚍⚎⚏ | 00 01 10 11 |
| 3 bit | 八卦 ☰☱☲☳☴☵☶☷ | 八进制一位 |
| 6 bit | 六十四卦 ䷀…䷿ | 操作码 |
| 门 / 触发器 | 与非门… / 锁爻器 | NAND… / flip-flop |
| 寄存器 | 卦器：乾兑离震巽坎艮坤 | r0–r7 |
| 运算器 / 时钟 / 内存 / 总线 | 算爻器 / 辰 / 藏 / 道 | ALU / clock / RAM / bus |
| 处理器 / 中断 | 太极 / 爻变 | CPU / trap |
| 系统调用 / 内核 | 叩 / 枢 | syscall / kernel |
| 进程 / 调度 / 虚拟内存 | 化 / 序 / 虚境 | process / scheduler / VM |
| 文件 / 目录 / 索引节点 | 籍 / 目 / 节 | file / dir / inode |
| 汇编器 / 编译器 / 模拟器 | 译卦器 / 译经器 / 演 | assembler / compiler / emulator |

命名不是随意的：**叩**（叩问于枢）、**化**（造化）、**藏**（藏而待取）、**爻变**（一爻之变，即状态迁移）——每个名都从汉字的本义里长出对应的概念，而非音译。这是「命名体系重建」与「翻译对照表」的分水岭。

### 3.2 爻机：二十四位字长之证

24 位 = 8 卦 = 8 个八进制位。择此数的三条理由：

1. **24 是 3 的整数倍**，卦与八进制边界永不撕裂（16 位做不到，此即 PDP 系列用八进制却未尽顺手的原因）。
2. **一个 24 位字 = 3 字节 = 正好一个 UTF-8 汉字**（基本区汉字与六十四卦符号在 UTF-8 中各占 3 字节）。按字寻址时，内存天然是「一字一汉字」。
3. 2²⁴ ≈ 16 M 字的寻址空间，足够承载一个教学用操作系统。

**两套位序，互为镜像，不可混用**：数值位序（`入[0]` 为最低位，用于一切运算与指令字段）与卦象位序（初爻为最高位，来自 Unicode 卦符的先天排布，用于书写与显示）。转换一律经 `排爻`/`并爻`/`倒爻` 三函数，其余各处不得自行换算。经核验：U+2630 段确为先天序（乾兑离震巽坎艮坤，`序位 = 7 − 值`）；U+4DC0 段为**文王序**（首乾末未济），与二进制序不同排列，映射表须查权威来源核对，**不得凭记忆手抄 384 条爻线**——此为 M3 之前置任务。

### 3.3 指令格式

```
甲型（寄存器型）  [6b 卦·操作码][3b rd][3b rs1][3b rs2][9b 功能位]
乙型（立即数型）  [6b 卦·操作码][3b rd][3b rs1][12b 立即数]    ← 12b = 4 个八进制位
丙型（跳转型）    [6b 卦·操作码][18b 地址]                      ← 18b = 6 卦
```

操作码 6 bit 正合六十四卦；寄存器号 3 bit 正合八卦；地址 18 bit 恰为六卦。**ISA 的每一个字段宽度都与易学符号体系的自然分组严丝合缝**——这不是巧合，是 24 位字长选择的推论。

### 3.4 模拟器「演」：三档抽象

| 档 | 粒度 | 用途 |
|---|---|---|
| L1 门级（爻级） | 逐门事件驱动求值，可见每一爻翻转 | 验证电路正确性；本工程目前所在 |
| L2 周期级 | 以「辰」为单位求值模块 | CPU 数据通路验证 |
| L3 指令级 | 直接解释 24 位指令 | 跑内核与操作系统 |

L1 与 L3 对同一程序给出一致结果，本身就是最强的正确性测试（交叉验证）。放弃 QEMU 作目标机的理由：为自研 ISA 写 QEMU target 需改 TCG 后端，工作量以年计；自研模拟器反而最便宜。

### 4.1 M0 阴阳与门：地基与「万门出于一」

**产出**：`爻.go`（阴阳与七种运算）、`象.go`（卦符与位序转换）、`门.go`（演 L1：线、门、网表、事件驱动调定）、`派生.go`（仅以与非门派生九门）、穷举测试十六项。

两条立意值得单独说明：

- **万门出于一**：一切门皆由与非门派生（与非门是万能门），测试以 `验纯粹` 断言网表中除 `*与非门` 外别无他种原语。这既是电路事实（NAND 逻辑完备），也是宣言——整台机器出自同一个原子，犹太极生两仪、两仪生四象之序。
- **异常当为一等公民**：三个非门首尾成环，`调定` 报「疑为振荡」而非死循环；两门共驱一线，`装门` 立时报错。模拟器的诊断能力从第一行代码就在设计之内。

验收：十六爻与门穷举 65 536 组，0.06 秒；异或恰由四与非门构成；译门（译码器）1–4 位共 298 组穷举。

### 4.2 M1 四象算术：以卦为操作码之始

**产出**：`算术.go`，自半加器、全加器、行波进位加法器、加一器、求补器、多择门，至**二十四位算爻器**（2 472 门 / 2 524 线）。

八种运算以三爻——**一卦**——择之，这是「以卦为操作码」第一次真正落地：

| 值 | 卦 | 运算 | 值 | 卦 | 运算 |
|---|---|---|---|---|---|
| 0 | 坤 ☷ | 加 | 4 | 震 ☳ | 逐位异或 |
| 1 | 艮 ☶ | 减 | 5 | 离 ☲ | 左移一爻 |
| 2 | 坎 ☵ | 逐位与 | 6 | 兑 ☱ | 右移一爻 |
| 3 | 巽 ☴ | 逐位或 | 7 | 乾 ☰ | 有符号比较 |

四志（标志位）：进位、零、负、溢出。

一处关键设计取舍：移位补零与减法进位需要恒定电平，取巧的 `NAND(a, ¬a)` 在事件驱动下会**先吐假值再复真——一次真实的毛刺**。故另立 `恒源` 为电源轨（有出无入，本非门也），「万门出于一」之验遂改为「凡受入而算者皆出于与非门，恒源不与焉」。

验收：八位加法器穷举 65 536 组；四位算爻器八操穷举 2 048 组；二十四位边界 800 例 + 随机 2 000 例与 Go 原生对拍。

### 4.3 M2 八卦时序：从电路到「机」

**产出**：`时序.go`——辰（时钟）、锁爻器（门控 D 锁存器）、边锁爻器（主从上升沿触发器）、存爻器、卦器堆（八器 × 24 位，6 693 门 / 6 729 线）、藏（RAM）、计爻器（程序计数器）。

> 前此一切皆是组合之电路：入变则出随，无所记忆，过而不留。
> 时序既启，这台机器方才有了「上一刻」与「下一刻」之分——**自此可以称「机」**。

本阶段解决了整个工程最微妙的理论问题，详于 §5.2 第八戒。

验收的高潮是**取指之机**：计爻器之出直接为藏之址，中间不假他物；藏中预置 `29j+3` 序列，计自增而逐条取出。特意取 `29j+3` 而非 `0,1,2,3…`：若诸值恰成等差一，则纵使地址线根本没接上、藏只是在自增，也能蒙混过关。测试里另设自败之验：诸值若近似等差一则直接 Fatal。**测试自己也得经得起怀疑。**

## 五、开发过程：方法论与戒律

### 5.1 先答理论问题，再动手

M2 动工前的第一个动作不是写代码，而是推演一个问题：**无延迟的事件驱动模拟器，能正确建模时钟边沿吗？**（门何时重算只看事件之序，不看时间；这与真实电路的传播延迟根本不同。）

答案：能，但有条件。主锁存器以反辰为启、从锁存器以辰为启。辰转阳之顷，从已开而反辰未及变，主犹透明；此时若「入」也在变，漏过主而达于从者便非沿前之值。但只要**入在辰翻转之顷稳定不变**，主纵透明，所存仍是沿前之值——**此即真实电路的建立时间与保持时间**。模拟器不必伪造延迟，而应把这条物理规律写成使用之约。

这个问题若不先答，写出的触发器会「有时对有时错」，错还无声——它只在特定求值顺序下现形，而那种顺序最难复现。

### 5.2 九戒：错误驱动的知识沉淀

本工程最重要的过程资产不是代码，是 `典/02-实现约束.md` 中的戒律。每一条都由真实的错误换来：

| 戒 | 内容 | 由来 |
|---|---|---|
| 六 | **凡位运算与算术混写，括号一律不省** | Go 中 `&` 与 `<<` 同级而左结合，`a - b & 掩` 实为 `a - (b & 掩)`；**同一类 bug 一日内咬了三次** |
| 七 | Shell 脚本变量名必须是 ASCII | `根="$(…)"` 被 `/bin/sh` 当成命令名执行，报错还指向路径，极易误判 |
| 八 | **先置入，后拍辰**（建立/保持时间之约）；三条推论：上电之态不可恃（锁爻器初态非法，收敛全凭求值之序，实测收敛为阳，故立`总复`复位轨）、不用门控时钟（防真机时钟偏移，纵模拟中此弊不显）、线之反相须共用（一根线只造一次非门，卦器堆中此一举省近两百枚门） | M2 理论推演与实测 |

其中「不用门控时钟」最能体现本工程的工程观：**纵在今日无延迟之模拟中此弊不显，此约亦当立——它防的是将来真机上的偏移，不是今日模拟里的错。模拟器的无延迟是模型的简化，不是物理的承诺。**

### 5.3 验证方法论

| 手段 | 实例 |
|---|---|
| 穷举 | 与门 65 536 组、加法器 65 536 组、译门 298 组——凡输入空间小者一律穷尽 |
| 对拍（差分测试） | 二十四位算爻器与 Go 原生运算对拍 2 800 例——凡穷举不动者找参照系 |

## 六、讨论：中文性的诚实分层

必须诚实回答：「中文」在这台机器里，何处是**结构事实**，何处是**记法**？

| 层 | 中文的存在方式 | 判词 |
|---|---|---|
| 物理层（门、电压） | 无关 | 与全世界的机器相同 |
| ISA 层 | 24 位 = 8 卦的字长切分、3 bit 寄存器编址 | **结构事实**（由字长选择保证） |
| 机器码层 | 操作码即卦 | **约定即事实**——约定一旦定下，编码即结构 |
| 汇编层（M4） | 汉字助记符 + 卦符号 | 记法，但独立存在、可 round-trip |
| 系统语言层（M8） | 汉字标识符（Lo 类合法） | **真实存在**——Go 已实证编译通过 |
| 系统调用层（M5） | 叩、64 卦序调用号 | 约定体系 |
| 用户程序层 | 汉字文件名、中文 shell、汉字字符串 = 一字一地址 | **结构事实**（UTF-8 3 字节 = 24 位字） |

尤其值得指出最后一行：因字长之择，「一字一汉字」不是愿望而是寻址的直接结果——**这台机器的内存天然以汉字为原子单位**，这是任何 8/16/32/64 位机器都不具备的性质。

与既有工作的关系：wenyan-lang（文言）已证图灵完备的中文语法语言可行，但面向宿主运行时，无裸机能力；本工程补的正是「从门到语言」之间缺失的整段。Сетунь 证明非二进制机器可行但死于生态；盘古刻意不与之竞争——底座仍是二进制，夺的是命名层。

局限：文王序 ↔ 先天序映射表未补（M3 前置）；藏之规模尚小（门级模拟撑不起兆级内存，届时须换档抽象）；坤恒为零的 zero-register 约定属 ISA 层、待 M3 数据通路实现；卦符号字形在多数等宽字体中缺失，工具链须保留 ASCII 回退。

## 七、结论

「中文操作系统」的可行路线，不是翻译，不是私用区造字，也不是改换物理底座，而是：**在二进制的坚实底座上，用中文与易学的符号体系，把计算栈自下而上的全部命名重做一遍。**

盘古开天用三个里程碑（约两日业余工期）验证了这条路的三个先决条件：

1. **语言条件成立**——全中文源码可编译，代价仅是单包架构与非中文标识符三处例外；
2. **数学条件成立**——24 位字长使卦、八进制、UTF-8 汉字三者边界重合，ISA 每个字段宽度与易学符号的自然分组严丝合缝；
3. **工程条件成立**——事件驱动模拟器上近万门电路、31 项测试全绿，且时钟边沿这类最微妙的问题可在无延迟模型中以「使用之约」忠实表达。

从机器语言到盘古系统的进化，是三次跃迁：**电路 → 语言**（M3 定 ISA，约定诞生，「语言」方始存在）、**语言 → 系统**（M4–M7，逐层为下层起更体面的名字）、**系统 → 自举**（M8–M9，用系统自己的语言写系统自己的工具）。贯穿三次跃迁的只有一件事——命名。**命名即抽象，抽象即系统；以中文命名，即得中文之系统。**
