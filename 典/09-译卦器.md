# 译卦器 · M4

**成于**：2026-09-02

> M3 之前，本机唯一的程序是 `程.go` 里那三段**手编**的机器码。
> 每一条都要人自己去算「操作码左移十八位，或上 rd 左移十五位……」。
> 一条算错，机器照跑不误，只是跑去了别处——**错，且错得悄无声息**。
>
> 译卦器所成者，是让人写「加数 艮, 坤, 10」，而由机器去算那些移位。
>
> 名字里的「卦」字不是装饰。助记符可以写汉字，也可以**直接写卦符**：
> ䷬ 便是 加数，☰ 便是 乾器，䷃ 便是数十。
> 卦符在源码里不是注释，是**字**——因为操作码本来就是一个别卦。

## 一、验收

`典/04-开天之图.md` 为 M4 所定之验收，原文是：

> round-trip 测试（汇编 → 机器码 → 反汇编 → 文本一致）

「文本一致」四字，须拆成两件事看。二者缺一，则验收是假的：

| | 所验 | 结果 |
|---|---|---|
| 一 | **字之往返**：`汇一(令之译(令)) ≡ 令` | **7 026 365 字，无一不合** |
| 二 | **段之往返**：`汇(反汇之文(诸令)) ≡ 诸令` | 斐波那契十一字，逐字相合 |

第一条是**穷举**的——把六十四卦之码全域扫过一遍，
不是「抽样看起来没问题」。全域之大，是 26 条实有之令 × 三型诸域之组合：

| 层 | 字数 | 何时跑 |
|---|---|---|
| 结构化之扫 | 10 621 | 每跑必验 |
| 定种之抽样（种 20260901） | 200 000 | 每跑必验 |
| **全域之穷举** | **7 026 365** | 设环境变量 `穷举` 方跑 |

前两层共 210 621 字，0.49 秒；全域那一层 14.75 秒。
**日常跑前两层，全域留给人去验**——此即「以闸分时」：
穷举之证要随时可取，却不必每次都付它的价钱。

## 三、双向之约

译卦器有**两个方向**：名 → 码（`汇`），码 → 名（`反汇`）。
这两个方向若由两张手抄的表各自维持，则增一令之时，改了一侧忘了另一侧，
便是**一侧认得、一侧不认得**——这种错不会报错，只会让某条令永远汇编不出来。

故立此约：

```
令名(码)  由 取型/分类 推出      —— 码 → 名
助记码表  由 令名 反推而造       —— 名 → 码
器号表    由 卦名/八卦符 推出    —— 器之名 ↔ 号
```

**三张表，一张也不是手抄的。** `Test译卦之表` 专验此约：
`len(助记码表)` 须等于 `len(有效之码)`（今为 **26**），
且凡 `取型` 判为未定之码，必不出现于表中。

增一令会怎样？在 `令.go` 里加一条，两侧同时长出来，一处都不必改。
**这本就是「单一事实来源」最朴素的样子。**

## 四、往返之验：令之译 与 令之辞

反汇编有两个函式，其别即「给机器读」与「给人看」之别：

| | 形 | 可读否 | **可回译否** |
|---|---|---|---|
| `令之辞` | `䷬ 萃 加数 艮, 坤, 10` | 好读——带卦符头与卦名 | **不可**（卦符头不在助记之位） |
| `令之译` | `加数 艮, 坤, 10` | 平实 | **可** |

`反汇` 用 `令之译`，不用 `令之辞`。此非偏好，是**约束**：
反汇编若吐出机器读不回的东西，那它就是谎言——
人读到的与机器执行的，便成了两件事。

> 由此得一条更普适的话：**凡「给人看」与「给机器读」分家之处，
> 二者必须由一个函式生出，或由一个函式验证。** 若各写一遍，
> 改了一处，另一处就成了假的——而两副面孔之中，必有一副是假的。

### 正体一律全写

规范式之三型：

```
甲型　助记 rd, rs1, rs2, 偏      偏以有符号书之（−256..255）
乙型　助记 rd, rs1, 数           数依 用符号 之约，符号者可为负
丙型　助记 址                    十八位之址，**恒书之**
```

一型几元，便书几元，**纵为零亦不省**：人写「停机」，机器出「停机 0」；
人写「加 震, 坎, 巽」，机器出「加 震, 坎, 巽, 0」。

三条理由：

1. **省址是糖，正体当全。** 糖若无对应之正体，便没了归处。
2. **甲型已先如此。** `等跃` 不用 rd，规范式仍书 rd（作 坤）——
   不用之域尚且书之，无义之址反而不书，是自相矛盾。
3. **例外之单是债。** 昔日此处写着 `码 != 停机 && 码 != 叩`，
   一张手抄的操作码名单。他日增一丙型之令而忘改此单，
   其反汇编便不可回译——而**往返之验未必察之**（详见 §九 盲区之三）。

## 五、语法

### 三型之令，与它们的糖

| 型 | 正体（反汇编所出） | 人写之糖 |
|---|---|---|
| 甲 | `加 震, 坎, 巽, 0` | `加 震, 坎, 巽`（省偏） |
| 甲 | `等跃 坤, 艮, 坤, 5` | `等跃 艮, 坤, 毕`（三元，标签为目标） |
| 乙 | `载字 震, 艮, 4` | `载字 震, [艮 + 4]`（括号之式） |
| 乙 | `载高 巽, 坤, 10` | `载高 巽, 0x00A`（`载高` 不用 rs1，故可省） |
| 丙 | `停机 0` | `停机`（省址） |

**糖不可替换正体。** 反汇编出的是正体，故正体必在，糖方有归处。
糖之设，非为炫技，而为**少写几个不错的东西**：
人写「环」，不必去数那三字；人写 `0xA`，不必去心算它的十进制。

### 卦符三用

卦符在源码里是**字**，不是注释。它有三处可用：

| 用 | 例 | 等于 |
|---|---|---|
| 为助记 | `䷬ 艮, 坤, 10` | `加数 艮, 坤, 10` |
| 为器 | `加 ☵, ☶, ☷` | `加 坎, 艮, 坤` |
| 为数 | `加数 艮, 坤, ䷃` | `加数 艮, 坤, 10` |

第三行最绕，须辨三事：

- 八卦符（☰..☷，U+2630 起）之值取**先天序**：`值 = 7 - (符 - 基)`，故 ☵ 坎 = 2。
- 别卦符（䷀..䷿，U+4DC0 起）之码位是**文王序**，须过 `文王先天` 才成先天值。
  ䷃ 蒙在文王序第四，其先天值 `(1<<3)|2 = 10`。**二者之间没有公式，只有一张表。**
- 故 `䷀`（文王序第一，先天 63）作数是 **63**，不是 0，也不是 1。

### 伪令二

| 伪令 | 用 |
|---|---|
| `处 址` | 定其后之码置于何址。跳址留隙，隙中之字为零 |
| `字 数…` | 径置一字之数据，不作令解 |

「伪」者，机器从不执行它们。`处 16` 之后那十三字的隙，
在 `藏` 里就是十三个零——而**零正是 ䷁ 坤 之码，即 停机**。
故演示中列 `藏` 之诸字时，不可径以 `令之译` 印之：
那样会把十三个隙全印成「停机」。**零与坤同码，非译卦之过，然示之于人不可不辨。**

### 标签

标签不占机器之码。一处极易忘之别：

- **甲型之偏是相对量**。书标签，则译卦器折算 `目标 − (本令址 + 1)`。
- **乙型之数与丙型之址是绝对址**。书标签，便是标签之址，不折算。

忘此别，则跳偏一个字——**错，且错得悄无声息**。

## 六、两遍之译

`汇` 跑两遍，因为标签可以**前引**：

```
第一遍   定址、记标签、报过；凡遇标签，暂填零
第二遍   折标签之值，径写诸字
```

一遍不成：`跃 环` 之 `环` 在其后三字，读到的那一刻还不知它在何处。

## 七、过而不止

译卦遇错**不立停**，尽其所能多报几处，每过皆带行号与原文。

> 一行之错，不该教人改一处再跑一遍。

此非体贴，是**效率**：汇编器若是「遇一错即返」，
那么一份有十处笔误的源码，就要跑十趟。

## 八、译数之序

`译数` 判一个数，其次序不可乱：

```
一、字符字面   '中'  → U+4E2D = 20013       （须最先：'中' 不以数起）
二、剥号       '-5'  → 号 = -1, s = "5"
三、标签       环    → 其址                  （须在剥号**之后**）
四、卦符       ☵ / ䷃
五、进制前缀   0x / 0X / 0o / 0O / 十进制
```

第三步若跑到第二步之前，`[艮 + 数区]` 中的「+数区」就查不到标签
（表里存的是「数区」，不是「+数区」），遂报「非数」。
**此病作者犯过，故志之。**

第一步之所以最先，是因为字符字面以 `'` 起而不以数起：
若先剥号，`'-'` 会被剥成一个 `-`，再无字符可认。

### 三处盲区

**七、界放宽一倍，竟无人察觉。** 十二位之数，有符号者 −2048..2047，
无符号者 0..4095。旧案只验了两头（0 与 9999），
中间那段 **2048..4095 之缝**从未验过。
界若放宽，`加数 艮, 坤, 3000` 会被**静默编成 −1096**——跑起来才错，错而无声。
遂补十三案，专塞其缝。

**十一、`反汇` 根本没有任何测试碰过它。** 何也？`反汇之文` 当时**另起了一个循环**，
自己又写了一遍 `令之译` 之逻辑，绕开了 `反汇`。
于是 `反汇` 成了无人之境——改坏了也没人知道。

修法不是加一个测试了事，而是**先去重**：令 `反汇之文` 委诸 `反汇`，
使「规范式长什么样」只有一处决定之地；再补 `Test反汇`，直呼 `反汇` 而验其可回译。
**去重在前，补验在后**——否则加的测试只是给那第二副面孔也盖了个章。

**十六、往返之验对它瞎。** 这一处与上面两处不同：
不是缺案，是**往返这个验法本身看不见它**。

`停机` 之址无义。书「停机 0」或书「停机」，回译皆得同一个字——
故 `汇一(令之译(令)) ≡ 令` 两式皆绿。
`Test往返穷举` 跑七百二十万字，**一个也杀不着**。

其时 `令之译` 之丙型写着：

```go
if 址 := 取址(令); 址 != 0 || (码 != 停机 && 码 != 叩) {
    return fmt.Sprintf("%s %d", 名, 址)
}
return 名
```

一张**手抄的操作码名单**，伏在格式化函数之中。
演示（丁）分明写着「停机 ≡ 停机 0」，而 `令之译` 出的是「停机」——
表上一副面孔，机器另一副。两张表自己不会吵。

治法有二，先正其形，后立其验：

1. **正形**：删去例外，丙型之址恒书。理由三条——
   *省址是糖，正体当全*（人写「停机」，机器当出「停机 0」，
   正如人写「加 震, 坎, 巽」，机器出「加 震, 坎, 巽, 0」）；
   *甲型已先如此*（`等跃` 不用 rd，规范式仍书 rd 作 坤——
   不用之域尚且书之，无义之址反而不书，是自相矛盾）；
   *例外之单是债*（他日增一丙型之令而忘改此单，其反汇编便不可回译，
   而往返之验未必察之）。
2. **立验**：`Test规范式之全`。它不验「回译得什么」，
   而验「规范式长什么样」——一型几元，便须书几元（甲四、乙三、丙一），
   诸元皆零与皆非零两式皆验。

> **瞎处须另立一验，不可委诸那双看得见的眼睛。**
> 一个验法验不到的东西，跑一万遍也是验不到——
> 它不会报错，它只是一遍遍地绿。

又：演示（丁）那张糖与正体之表，自此**自己验自己**——
右二列一验同码（`汇一(糖) ＝ 汇一(正)`）、
一验同式（`令之译(汇一(糖)) ＝ 正`）。
表上写的与机器出的，须是同一件事；而两张表自己不会吵，须人教它吵。

### 变异之器自身亦须可信

此番另得一条，比上面两处盲区更要紧——它不是 `译.go` 之病，是**量具**之病。

变异之器以 zsh 书成（shebang `#!/bin/zsh`），而作者尝以 `bash` 呼之。
bash 不纳多字节变量名，于是：

- `果=`、`何=`、`由=` 皆成「命令未找到」，`果` 恒为空；
- `${由}` 触发 bad substitution，**中断了函数体**；
- 函数体既断，末尾那行「还原」便从未执行——十五个变异**累积叠加**在 `译.go` 上；
- 而每一次，皆因 `果` 为空被判成「已杀」。

结局是：一份处处是错的 `译.go`，配一份「十五皆杀」的报告。
**一具坏掉的量具说「尽杀」，比没有量具更害人——它教人信了不该信的。**

故器成之后，又立五检：

1. **注入之检**——变异前后校验和须变；不变则报「未注入」，**不以「已杀」饰之**。
   未注入之变异本就杀不着，把它算作「已杀」是自欺。
2. **还原之检**——还原置于每试之**前**（而非之后），纵中途断亦不致累积；
   收工之后再校校验和，与原样不符则止。
3. **首尾之检**——开跑之前、收工之后，各跑一遍全验，须皆绿。
4. **自检**——注入一个**无害**之变异（改一句注释），验此具报「存活」。
   一具若连「有变异」都分不出，它报的「尽杀」便什么也不说明。
5. **验数之检**——数一数包内实有几验、实跑几验，二者当同（今为 78 验）。
   第五检之立，缘于一件丑事，见下。

> **量具亦须被量。** 一个说「一切正常」的检查，
> 必须先证明它**分得出不正常**——否则它的沉默什么也不说明。

### 同一病之第三发：手抄之单

第五检之立，缘于一件丑事。

变异十六（丙型之址为零者不书）初跑，报「**存活**」。
而 `Test规范式之全` 明明专为杀它而立，且单跑它确实杀得死。
何以报存活？**因为它从未被跑。**

彼时 `具/变异译.sh` 之中有一行：

```sh
PAT='Test译卦|Test分行|Test译数|Test往返|Test手编|Test伪令|Test糖与正体|Test标签|Test译过|Test反汇'
run() { ./跑.sh test -count=1 -run "$PAT" ./... 2>&1; }
```

一张**手抄的测试名单**。单子写就的那日，它是全的；第二日便不是了。
新立之验不在单上，于是从未被跑——而脚本**不会报错**，
它只会在变异存活时报「存活」，教人去查一个其实并不存在的洞。

此是同一病之**第三发**：

| 发 | 手抄者 | 治法 |
|---|---|---|
| 一 | `器号表`（器名 → 0..7） | **双向之约**：径由 `卦名` 导出，不抄 |
| 二 | `助记码表`（助记 → 码） | 同上，径由 `分类`/`分操`/`卦名` 导出 |
| 三 | `PAT`（该跑哪些测试） | **不抄，便无从漏**：整包之测不过六秒，全跑即是 |

三发之治法是一句话：**一处知识若有两份拷贝，其中一份必朽。**
而朽的那份若是个**过滤器**（名单、`-run`、白名单），
它漏掉的东西不报错，只是**不见了**——这是最难察的一类错。

故 `PAT` 已废。整包之测不过六秒，全跑即是；
又立**验数之检**，把「几验被跑」这个数印出来，教此类事看得见。

## 十一、本机读出的第一个汉字

`字 '中'` 之中，是 U+4E2D = 20013，恰满一字二十四位。
此非巧立名目：`典/01` 定字长为三字节，而三字节正是一个汉字之码位。

```
处 16
数区：字 '中'
      字 '文'
```

跑之，`震 = U+4E2D = '中'`。

> 故本机读一个汉字，与读一个数，是同一件事——**它本无分别**。
> 分别只在人心里：人把 20013 认作「中」，机器只认得那二十四根线。
