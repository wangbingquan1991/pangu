# 实现约束：为什么全中文意味着单包

本文件记录三条由实测得出的硬约束。它们不是设计偏好，是 Go 语言与 Unicode 的既定事实，
违背其中任何一条，代码就不能编译。

## 一、汉字标识符一律不可导出

Go 语言规范：标识符以其**首字符是否为大写字母（Unicode 类 Lu）**决定导出与否。
汉字在 Unicode 中属 **Lo（Letter, other）类，不是 Lu**，故：

```go
type 爻 bool      // 包外不可见
func 造() 爻      // 包外不可见
func Run() 爻     // 唯一可见者（R 是 ASCII 大写）
```

实测（`go doc -all .`）：包中只列出 `Run`，其余中文标识符一个也未出现。

**后果**：跨包调用中文标识符是不可能的。因此——

> **全中文 ⇒ 整个系统必须是同一个 Go 包。**

这不是偷懒，是语言规则逼出来的唯一解。目录结构上表现为：所有 `.go` 源文件平铺在
仓库根，共享 `package 盘古`。分层靠文件名前缀与文件内的分节注释维系，不靠目录。

## 二、Go 包名可以是中文，导入路径的目录名不可以

实测三条：

| 试法 | 结果 |
|---|---|
| `package 盘古` | ✅ 合法，可编译 |
| `import "pangu"` 后以 `盘古.Run()` 引用 | ✅ 合法（Go 以源码声明的包名行限定引用，非以导入路径末节） |
| 目录名含汉字，如 `pangu/cmd/演武` | ❌ `malformed import path "pangu/cmd/演武": invalid char '演'` |

**后果**：

- 模块路径 `pangu` 用 ASCII（写在 `go.mod`）。
- 任何**需要被 import 的**目录名必须是 ASCII，故命令行入口放在 `cmd/pangu/`。
- 不需要被 import 的目录（如 `典/`，只放 Markdown）**可以用中文名**，因为它们不参与构建。

## 三、测试函数必须带 ASCII 的 `Test` 前缀

`go test` 只识别名字以字面量 `Test` 开头的函数。故测试函数写作 `Test译门`——
`Test` 是工具链强求的，其后部分为中文。此与 `Run` 同属「仅此若干处用非中文」之列。

同类约束还有：`Benchmark`、`Example`、`Fuzz` 前缀。

## 四、非中文出口的清单（应始终极短）

全系统允许出现非中文标识符的地方，仅以下三处：

| 位置 | 名称 | 理由 |
|---|---|---|
| `go.mod` | `pangu` | 模块路径不得含非 ASCII（见约束二） |
| `出口.go` | `Run()` | 包外唯一入口，中文标识符不可导出（见约束一） |
| `*_test.go` | `Test` 前缀 | `go test` 的发现规则（见约束三） |

## 五、Go 工具链的位置

Go 未装入系统 PATH，而装在隔离目录：

```
GOROOT = ~/.workbuddy/binaries/go/go
GOPATH = ~/.workbuddy/binaries/go/gopath
GOCACHE = ~/.workbuddy/binaries/go/gocache
```

版本 go1.27.0 darwin/amd64（Intel i5-8500）。
仓库根的 `跑.sh` 会自动设好这三条，用法：

```sh
./跑.sh test ./...       # 跑测试
./跑.sh run ./cmd/pangu  # 跑演示
./跑.sh vet ./...        # 静态检查
```

> 曾尝试 `brew install go`，被两件事挡住：沙箱拒绝写
> `/usr/local/var/homebrew/locks/`，且 `/usr/local/share/man/man8` 属主非当前用户。
> 遂改为下载官方 tarball 至隔离目录，不触碰系统目录。

## 六、位运算之戒：Go 的 `&` 与 `<<` 同级

**同一类 bug 在 M1 一天之内咬了三次**，故单独立戒。

Go 的运算符优先级中，位与算移属于同一级：

```
5:  *  /  %  <<  >>  &  &^      ← & 与 << 同级
4:  +  -  |  ^                  ← - 比 & 低一级
```

同级者左结合。于是：

| 写法 | 实际所算 | 意图 |
|---|---|---|
| `a - b & 掩` | `a - (b & 掩)` | `(a - b) & 掩` |
| `v & 1 << (位-1)` | `(v & 1) << (位-1)` | `v & (1 << (位-1))` |
| `1<<位 - 1` | `(1<<位) - 1` | 同，此例侥幸无误 |

**戒律：凡位运算与算术混写，括号一律不省。** 掩与符位先赋给命名的变量
（`掩 := 1<<位 - 1`、`符位 := 1 << (位 - 1)`），再参与运算，可免此祸。

本戒已体现于 `算术_test.go` 的 `欲算` 与 `演示.go` 的 `演示算爻` 两处注释中。

## 七、Shell 不接受非 ASCII 变量名

`/bin/sh`（dash / POSIX 模式下的 bash）的变量名只允许 ASCII 字母、数字与下划线。
故 shell 脚本——包括 `钩/pre-commit`——**注释与输出可用中文，变量名不可**。

```sh
根="$(git rev-parse --show-toplevel)"   # ✗ 报「根=...: No such file or directory」
ROOT="$(git rev-parse --show-toplevel)" # ✓
```

报错信息把赋值整行当成命令名，极易误判为路径问题。此坑已踩过一次。

惟 Git 的钩子**文件名必须是 ASCII**（`pre-commit`），故钩子置于中文目录 `钩/` 之下，
文件名本身仍是 ASCII。以 `git config core.hooksPath 钩` 启用。

### 第二次踩：同一坑，静默的失败

第一次踩，报的是「No such file or directory」，一眼可见。
第二次踩（M4 之变异测试器），**报的是「尽杀」——而其实一处也没验到**。

变异之器以 zsh 书成（shebang `#!/bin/zsh`），而执行时用的是 `bash`。
bash（非 zsh）不纳多字节变量名，于是：

```sh
果=$(...命令...)    # bash 不认 果 为变量名 → 视「果=$(...)」为一条命令
                    # → 命令替换之结果参与词分割 → 首词「果=---」被执行
                    # → 「果=---: command not found」，而 果 恒为空
echo "${由}"        # → bad substitution，且**中断所在函数体**
```

函数体既断，写在末尾的**还原语句便从未执行**——十五个变异**累积叠加**在被改的源文件上；
而每一次，判据 `echo "$果" | grep -q '^ok'` 因 `果` 为空而恒为假，遂**一律报「已杀」**。

结局：一份处处是错的源码，配一份「十五变异十五皆杀」的报告。

**教训（比「变量名用 ASCII」更进一层）**：

1. 脚本既以 `#!/bin/zsh` 起，便**以 zsh 呼之**（`zsh 脚本`），勿径用 `bash`。
   shebang 只在「直接执行」时生效，交给解释器时它是无效的。
2. 纵然只用 ASCII 变量名，也要**防「静默的成功」**：一个说「一切正常」的检查，
   必须先证明它**分得出不正常**。见 `典/09-译卦器.md` §九，及下之第十戒。

## 八、时序之约：先置入，后拍辰

本模拟器**不建传播延迟之模型**——一线之负载何时重算，只看事件之序，不看时间。
于是无延迟之时序便有一问：主从触发器的边沿还能正确否？

能，但有条件：辰 既转阳，从锁存器已开，而 反辰 尚未及变，主锁存器犹透明。
此时若 入 也正在变，则漏过主而达于从者便非沿前之值。
只要 **入 在辰翻转之顷稳定不变**，主纵透明，所存者仍是沿前之值，结果无差。

此即真实电路的**建立时间与保持时间**。本模拟器把它写成使用之约，而非电路之律：

> **凡欲写某器，须先置其入、置其存允，待调定已安，方可拍辰。
> 拍辰之后，方可更其入。**

违此约者，未必立错，然错则无声——它只在特定的求值顺序下才现形，
而那种顺序恰恰是最难复现的。故 `时序.go` 中诸器一律按此约使用，测试亦按此约而写。

**相关的三条推论**：

1. **上电之态不可恃。** 锁爻器之初态是「两出皆阴」的非法之态
   （线的零值即阴，而 Q 与 Q̄ 互为对方的出），收敛到哪一态全凭求值之序。
   实测初始收敛为阳。故凡用寄存器者，必先 `辰.复位()`。
2. **不用门控时钟。** 写寄存器时以 存允 择其入，而非以 存允 去与 辰
   令各器自生其时钟。后者有时钟偏移之患：快者已纳而慢者未及，一拍之内诸器不齐。
   纵在今日无延迟之模拟中此弊不显，此约亦当立——它防的是将来真机上的偏移。
3. **凡线之反相，须共用。** 时序电路中一根线的反相常被数百处引用
   （如 反辰，诸锁爻器皆须之）。故有 `网表.反相(w)`：同一线只造一次非门，
   以 `反表` 记之。二十四位卦器堆之中，此一举省下近两百枚门。

## 九、字体

U+4DC0 段的六十四卦符号在多数等宽字体中无字形。建议装
Sarasa Mono（更纱黑体）、Noto Sans Symbols 2 或 BabelStone Han。
工具链的输出保留 ASCII 回退的余地。

## 十、量具亦须被量

M3 得一训：**对拍全绿，不等于处处验到**——验之疆界须以变异测试量之。
M4 又得一训，比它更进一层：

> **量具亦须被量。**
> 一个说「一切正常」的检查，必须先证明它**分得出不正常**——
> 否则它的沉默什么也不说明。

变异测试器是一次实践。它的五道自检，凡「自动判定之事」皆可照搬：

1. **注入之检**——变异前后校验和须变；不变则报「未注入」，
   **不以「已杀」饰之**。未注入之变异本就杀不着，把它算作「已杀」是自欺。
2. **还原之检**——还原置于每试之**前**（而非之后），纵中途断亦不致累积；
   收工之后再校校验和，与原样不符则止。
3. **首尾之检**——开跑之前与收工之后各跑一遍全验，须皆绿。
   这两检之间若出了岔子（脚本中断、变量为空、命令不存在），必现于尾之检。
4. **自检**——注入一个**无害**之变异（如改一句注释），验此具报「**存活**」。
   一具若连「有变异」都分不出，它报的「尽杀」便什么也不说明。
   前三检防的是「器坏而不知」，此检防的是「器根本没在量」。
5. **验数之检**——数一数包内实有几验、实跑几验，二者当同。
   此检之立缘于一件丑事，见下。

**同理可推及一切自动之验**：对拍器、回归脚本、CI 之门禁、
乃至「测试全绿」这句话本身——**先问它能不能红，再信它的绿。**

### 凡手抄之单，必漏

变异测试器之中，曾有一行：

```sh
PAT='Test译卦|Test分行|Test译数|Test往返|…'
run() { ./跑.sh test -count=1 -run "$PAT" ./... 2>&1; }
```

一张**手抄的测试名单**。单子写就的那日，它是全的；第二日便不是了。
新立之验 `Test规范式之全` 不在单上，于是**从未被跑**——
而脚本不会报错，它只在变异存活时报「存活」，
教人去查一个其实并不存在的洞。

这是同一病之第三发：

| 发 | 手抄者 | 治法 |
|---|---|---|
| 一 | `器号表`（器名 → 0..7） | **双向之约**：径由 `卦名` 导出，不抄 |
| 二 | `助记码表`（助记 → 码） | 同上，径由 `分类`/`分操`/`卦名` 导出 |
| 三 | `PAT`（该跑哪些测试） | **不抄，便无从漏**：整包之测不过六秒，全跑即是 |

> **一处知识若有两份拷贝，其中一份必朽。**
> 而朽的那份若是个**过滤器**（名单、白名单、`-run` 之选），
> 它漏掉的东西**不报错，只是不见了**——这是最难察的一类错。

故 `PAT` 已废，整包全跑；又立**验数之检**，把「几验被跑」印出来，
教此类事看得见。

### 另一面：去重在前，补验在后

M4 有一变异存活，其因不是「少了一个测试」，而是**同一件事有两处决定之地**：
`反汇之文` 另起一个循环，自己又写了一遍规范式之逻辑，绕开了 `反汇`。

此时若只补一个测试去覆盖 `反汇`，那测试不过是**给第二副面孔也盖了个章**——
两处仍在，错仍会发生。故修法次序不可颠倒：

> **先去重，使「真相」只有一处；后补验，使那一处有人看着。**

### 再一面：瞎处须另立一验

`停机` 之址无义。书「停机 0」或书「停机」，回译皆得同一个字——
故 `汇一(令之译(令)) ≡ 令` **两式皆绿**。
`Test往返穷举` 跑七百二十万字，一个也杀不着「丙型之址为零者不书」这个变异。

这不是缺案，是**往返这个验法本身看不见它**。
往返验的是「回译得什么」，而病的却是「规范式长什么样」——
前者两式同果，故后者无论怎么错，前者都绿。

> **一个验法验不到的东西，跑一万遍也是验不到。**
> 它不会报错，它只是一遍遍地绿。
>
> 故：**凡改了一个函式的「形」，须问一句——
> 现有的验，是验它的「果」，还是验它的「形」？
> 若只验果，形错了谁管？**

此问之答是 `Test规范式之全`：不验回译，而验形——
一型几元便须书几元，诸元皆零与皆非零两式皆验。

同类者可推：对拍验的是「L1 与 L2 同果」，
若二者同错，对拍便瞎——M3 之「十三变异」正是为此而立。
