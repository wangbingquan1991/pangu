# 太极运化 · M3

**成于**：2026-09-01

> M0 造了门，M1 造了算，M2 造了记忆与时刻。
> 三者皆备，而机器犹不能「做事」——因为它们之间还没有那根把它们串起来的筋。
> M3 所成者，就是这根筋：**一条数据通路，加一个控制单元，再加一套指令集**。
>
> 自此，这台机器第一次能读懂一串数字，并按数字的意思去改自己的状态。
> 这便是**运化**。

## 一、验收

`典/04-开天之图.md` 为 M3 所定之验收，原文是：

> 跑通一段手写的 24 位机器码（如计算斐波那契），L1 与 L2 结果一致。

此验收分上下两半，皆已成：

| | 所验 | 结果 |
|---|---|---|
| 上半 | `太极`（L1，门级）独跑手编之斐波那契 | **132 拍，离 = 55 = fib(10)** |
| 下半 | `周期`（L2，周期级）与 L1 **逐拍对拍** | **13 案 324 拍，处处相合** |

**为何 程.go 要另立一文件？** 两个理由，各是一次撞墙：

- Go 的 `_test.go` 只在 `go test` 之下编译，演示（生产代码）引用不到其中的标识符。
- 程序不是「测试用的样本」，它是本机的公产。把它锁在测试文件里，
  等于说这台机器跑过的唯一一段程序，只能在不跑它的时候才看得见。

## 三、指令集：以卦为码

一令二十四位。高六位是操作码，正合一**别卦**——六十四卦，六十四码。

**编码之理**：六位操作码取**先天值**，`值 = (上卦 << 3) | 下卦`，
于是八进制写法 `码 = 0o(上卦)(下卦)` —— **上卦定其类，下卦定其操**。

这不只是好看。上卦直接接译门，下卦直接接算爻器的三根择线；
数类（兑，6）与器类（乾，7）之下卦，正是 M1 算爻器的八操之号。
**一个多路器都不必加**——M1 的择线与 M3 的操作码，是同一组线。

三类之形：

| 型 | 布局 | 所用 |
|---|---|---|
| 甲型 | `[6 码][3 rd][3 rs1][3 rs2][9 偏]` | 器与器之算、条件转移 |
| 乙型 | `[6 码][3 rd][3 rs1][12 立即数]` | 器与数之算、存取 |
| 丙型 | `[6 码][18 地址]` | 无条件转移、停机、叩 |

十七令、算爻十六令之全表，见 `典/01-爻机规格.md`。

**一处必志之戒**：`取*` 与 `分*` 是两族，不可混。

- `取码 取rd 取偏 取立即数` 入参是**二十四位之令**；
- `分类 分操 用符号` 入参是**六位之码**。

初写时以 `取上卦`/`取下卦`（二十四位入）去解一个六位之码，
于是六十四卦尽落坤下——反汇编把每一条指令都印成 `䷁ 坤 停机 0`。
此病之状极醒目，而其因极微：两族同名，只差入参之宽。

## 四、数据通路

`太极.go` 之 `置太极` 分十一节，自预装载之口起，至闭合其环止。其筋络是：

```
         ┌──────────┐
  藏 ────┤  令器     │─── 译码 ── 上卦定类、下卦定操
   │     └──────────┘                │
   │                                 ├─→ 择（算爻之操）
   │     ┌──────────┐                ├─→ 堆存允、藏存允
   └─────┤  藏址之择  │◄── 计 / 果 / 预址   └─→ 写回之择（果 / 藏出 / 高数 / 计）
         └──────────┘
              │
   ┌──────────┴───────────┐
   │   卦器堆 ──→ 算爻器 ──→ 果   │
   │      ↑                  │    │
   │      └──── 写回 ─────────┘    │
   └───────────────────────────────┘
```

四事值得一说：

**一、两级译码。** 六位直译六十四，须七百七十四门；分作两级 3→8，只用百二门。
省下的不是门，是**译码之形**：上卦之出是「类」，下卦之出是「操」，
两者在电路里本就是两件事，硬并成一层反而看不清。

**二、算爻器只有一座。** 存取之地址（基址 + 偏移）、条件转移之比较、
算爻指令之运算，三者皆过同一座算爻器。这不是省门的将就：
算爻器是**组合**的，同一拍之内只有一件事在用它，本不必有二。

**三、跃用另一座加法器。** 相对转移要算 `计 + 偏`。计 是十八位，
偏 是九位，故用一座**十八位**加法器（百六十二门）即可；
若去过二十四位的算爻器，则须在它的甲口加一重二十四位择门（百九十二门），
且那重择门还要挤占本来给立即数用的通路。**窄的更省，且更清。**

**四、坤恒为零。** 规格有此一条，M2 的卦器堆是通用的（八器皆可写），
故留到 M3 来实现：写允许 ∧ 全或(rd 之三位)。全或门八枚足矣；
若在堆内译码，则须五十一门。

## 五、控制单元：两拍一令

藏 之读是**组合**的——址一变，字立出，不等沿。
于是取指与执行不可同拍而毕：**一拍取令，一拍行之**。

```
取指相（相 为阴）   藏址 ← 计        令器 ← 藏[计]       计 ← 计 + 1
执行相（相 为阳）   算、存取、跃，各依其码
```

自反汇编之迹看去，便是 `相` 在「取指」「执行」之间逐拍而翻：

```
 拍 │ 相  │ 计 │ 令（八卦）
  1 │ 执行 │ 01 │ ☱☷☶☷☷☷☶☵   取指毕，令已入器
  2 │ 取指 │ 01 │ ☱☷☶☷☷☷☶☵   执行毕，艮 = 10
  3 │ 执行 │ 02 │ ☱☷☵☷☷☷☷☷
  ...
 18 │ 取指 │ 03 │ ☳☷☷☷☷☷☷☴   跃 3 已行，计 回三
```

### 四坑

以下四事，皆是先想明白了才动手的。若径直写去，四者皆能跑，而四者皆错——
**错而无声**，正是门级电路最凶之处。

**一、停机须同时封住令器。** 只封 计 是不够的：下一拍 相 翻回取指相，
令器 又会去 藏 里取一条新令，机器遂在「已停机」之后又跑了一步。
故 令器、计 皆须受 `¬止` 管辖。

**二、止 必须是粘滞的寄存器，不能是组合信号。** 复位之后 令器 为全零，
而**全零正是停机之码**。若 `止 = (码 == 停机)`，则上电即自锁，机器永不能启动。
故 止 用寄存器，且只在**执行相**置位：复位时 相 为阴（取指相），止 遂为阴。

**三、算爻之择不可直连 令 之下卦。** 存取类（坎上）也要用算爻器算地址，
那时它要的是「加」，而不是 令 之下卦所表的那个操（比如「存字」的 1）。
故 `择 = 与(是算爻, 令[20..18]) ∨ 是较跃 ∨ 是比跃`——
**下卦只在真的算爻之时才作数。**

**四、装载期间须封住相爻器。** 预装载是「外力直接写藏」，
与两相之机不同源。装载期间若 相 乱翻，则 计 也会被自增，装载之址遂错。
故 `相之存允 = ¬预 ∧ ¬止`；又，**复位必须在装载之前**。

## 六、以慢御快：L1 与 L2

| | 太极（L1） | 周期（L2） |
|---|---|---|
| 所算 | 门。三万三千余门，逐门重算至定 | 整数。一门也无 |
| 一拍 | 3.19 ms | 17 ns |
| 速 | 1× | **约 19 万倍** |
| 可信否 | 可信——全身无一句「假设」，它是从与非门搭起来的 | 不可自信——**全身都是假设**：假设数据通路是那样连的、假设时序是那样走的。假设错了，它照样跑得欢 |

故 L2 之可信不由其自身证明，而由 L1 一拍一拍地替它证明。
**慢者是尺，快者是布；布之长短，须以尺量之，不可自夸。**

同一段累加 1..1000 之码：L2 实跑 6006 拍，103.8 µs；
同一段码若以 L1 跑之，按实测之每拍计，须 **19 秒**。

### 同时之变

L2 之一拍，须**自旧态算出诸新，再一并纳之**。
若随算随写（先写 计，再用新的 计 去取指），所得者是串行赋值之果，
而非一拍同时之果——**错，且错得悄无声息**。

故 `周期.go` 之 `步` 分两段：先尽取 `旧计 旧令 旧相 旧器 旧字`，
算出 `新计 新令 新相 新器 新字`，末了才一并纳之。

## 七、对拍

对拍之法：同一段机器码，两机并跑，每拍之后比其全态
（计、令、相、止、八器、诸字），一处不合即止。

**十三案**：

| 案 | 所攻 |
|---|---|
| 斐波那契 | 循环、条件转移、相对跃与绝对跃之并用 |
| 存取 | 存字、载字、载高、并数 |
| 八操 | 甲型八操，施于小正数 |
| 符号 | 甲型八操，施于**负数**（降 之逻辑/算术、升 之截顶、较 之符号） |
| 负数 | 乙型立即数之负（加减较符号扩、交并殊零扩） |
| 四跃 | 等跃、异跃、逊跃、胜跃 |
| 负偏 | 负偏移之编码 |
| 坤恒零 | 写入坤，当被吞 |
| 叩 | 叩 置 止 |
| 自改 | 藏 中之码改后，下一条所取者 |
| 越址 | 计 之宽与 藏址 之截 |
| 停机 | 停机 之后全机当定 |
| 空 | 唯 停机 一令 |

凡 **324 拍**，处处相合。

### 变异测试：验「验」之验

十三案一次跑绿。一次就绿的对拍**值得怀疑**——
它也可能是因为两边的错刚好抵消，也可能是因为根本没验到要害。
遂以**变异测试**为绳：故意把 L2 改错，看诸案能否杀之。

| 变异 | 结果 |
|---|---|
| 降 改算术右移 | 杀 |
| 升 不截顶 | 杀 |
| 较 改无符号 | 杀 |
| 立即数一律零扩展 | 杀（初曾存活，见下） |
| 取指相 计 不自增 | 杀 |
| 相 恒为执行 | 杀 |
| 坤可写 | 杀 |
| 执行相仍以 计 为藏址 | 杀 |
| 跃之偏一律零扩展 | 杀 |
| 丙型跃 改相对 | 杀 |
| 抹去 跃志 取反 | 杀 |
| 存字 之 rd 不反作源 | 杀 |
| 载高 不移位 | 杀 |

**十三变异，十三皆杀。**

### 变异之所获：两处盲区

**一、「降 改算术右移」杀不掉。** 何也？旧案之八操皆施于小正数，
而逻辑右移与算术右移，在正数之上同果——**验之如不验**。
遂补「符号」一案，八操施于负数，变异立现。

**二、「立即数一律零扩展」曾存活。** 何也？乙型立即数旧非小正数即偏移，
而偏移走 `取偏`（甲型九位），不经 `扩立即数`。
遂补「负数」一案，专验 `用符号` 之约：加减较符号扩，交并殊零扩。

由是得一教训，比那两个补案更要紧：

> **对拍全绿，不等于处处验到。**
> 验之疆界，须以变异测试量之，不可以其自身之言信之。

### 对拍之疆：三处验不到

`周期.go` 之首志了三则，此处摘录其一——最要紧的那则：

**存取之符号扩展，在 址 ≤ 12 时不可观测。**
藏址 = 果 & 址掩，而符号扩与零扩之差恰是 2¹² = 4096；
址 ≤ 12 时 4096 ≡ 0 (mod 2^址)，二者遂无别。
故 `用符号` 之于存取，对拍验不到；它之所以仍在，是因为**语义当如此**，
且他日 址 大过十二便有用。**今之无用，非其罪。**

## 十、M3 之三约

1. **取\* 与 分\* 之别。** `取码`/`取rd`/`取偏` 之入参是 24 位之**令**；
   `分类`/`分操`/`用符号` 之入参是 6 位之**码**。二类同名而实参不同。
   混用则六十四卦尽落坤下——每一条令都被解成 `䷁ 坤 停机 0`，
   机不报错，只是**一动不动**。
2. **同时之变。** 一拍须**自旧态算出诸新，再一并纳之**。
   随算随写，所得是串行赋值之果，而非一拍同时之果——错且无声。
   （此条后入 `典/02` 为第九戒。）
3. **以慢御快。** L1 可信而慢（3.2 ms/拍），L2 快而不可自信（17 ns/拍）。
   L2 之可信不由其自身证明，而由 L1 逐拍对拍证明。
   **慢者是尺，快者是布；布之长短，须以尺量之，不可自夸。**
