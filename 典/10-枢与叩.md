# 枢与叩 · M5

> **验收**（`典/04` 原文）：用户态程序执行「叩」，内核接管并通过串口打印汉字。
> **这是第一个「操作系统」闭环。**
>
> 已达。跑 `./跑.sh run ./cmd/pangu`，第七节末了出：
>
> ```
> （丁）开天：94 拍，出「盘古开天！」
> ```
>
> 那五个字**是码打出来的**——枢不是 Go 写的函数，是译卦器汇出来的机器码，
> 由 叩 跳进去，由它自己写器区，再由 回 返回。Go 那一侧只做机器
> **本该由电路做**的三件事：特权、爻变、器区。

## 二、L3 何以可信：抽线，不抄式

L1 之可信，由门数之穷举证。L2 之可信，由与 L1 **逐拍对拍**（`典/08`）。

**L3 之上再无 L4 可对其拍。** 故其可信须另走两路：

### 其一：证明它什么也没做

L3 **不重算一条令**。一拍之实，尽委 `周期机.步`；L3 只在 步 之前后加三件
L2 所无之事——特权、爻变、器区。此三者 L2 中本来没有线，故非「改」而是「加」。

凡 L2 中已有的线，L3 一律委之，**不另抄一式**。藏址便是一例：
L3 用 `机.址值()` 这根探针，而不自算 `果`。自算便是抄，抄了便有两处可独改。

> 此即 `典/09`「双向之约」之推广：**一处知识只有一份。**
> 一份者，改之则处处随；两份者，改其一而另一静默地朽。

`Test枢与周期对拍` 专守此条：同一段码，L2 与 L3 逐拍处处相合。

| 程 | 拍 |
|---|---|
| 斐波那契 | 132 |
| 存取与载高 | 14 |
| 处与字 | 6 |
| 累加二十 | 126 |
| 累加百 | 606 |
| **共** | **884 拍**，计/令/相/址/拍/诸器/诸字 无一不合 |

此验若绿，则 L3 未曾动过指令语义；若红，则 L3 抄了或改了。

### 其二：量它新加的那三件事验到了什么

「验到了什么」**不能靠自陈**。一个说「一切正常」的检查，
必须先证明它**分得出不正常**。故立 `具/变异枢.sh`：廿五变异，廿五皆杀（§九）。

## 三、藏之图

```
0o000000  启          一令：降化 化之始
0o000100  化之码      用户程，全在化态
0o000200  化之数      用户数据：欲言之辞
   ⋮      （未写）    留与后之里程
0o777000  叩之表      六十四槽，一槽一条 跃
0o777100  变之表      三槽，一因一槽
0o777200  枢之正文    叩之服务与变之处理器，二十八字
   ⋮      （未写）
0o777770  器区        八口，非藏：出、志、入
```

| 常量 | 值 | 义 |
|---|---|---|
| `枢基` | `0o777000` | 枢之域之始。自此以上，化态一步不许入 |
| `化之极` | `= 枢基` | 化之域之上界（不含） |
| `叩之表基` | `= 枢基` | 六十四槽 |
| `变之表基` | `枢基 + 0o100` | 三槽 |
| `枢文基` | `枢基 + 0o200` | 枢之正文 |
| `器基` | `0o777770` | 器区八口，居藏之极 |

**取 0o777000 而非他数之故**：藏之址十八位，其上界是 `0o777777`；
留 `0o1000`（五百一十二字）与枢，恰是藏之 1/512——
一个「刚好够放一张表和几段处理器」之数，不是一个圆整好看之数。

### 是枢之域 之界，由 化之极 出，不由 枢基 出

```go
func 是枢之域(址 int) bool { return 址 >= 化之极 && 址 <= 址掩 }
```

二名虽同指一址，然「非化之域」是**因**，「枢基」是**果**。
由因出果，则改其一而另一自随；由果抄果，则两处皆可独改而无声。

变异廿三专守此条：改 `是器区` 之界使之一字之差，若界是抄来的便杀不着。

## 四、特权：两态与三禁

| 态 | 名 | 义 |
|---|---|---|
| 化态 | 用户态 | 触枢之域则越权，行特权之令则越权，唯 叩 是门 |
| 枢态 | 内核态 | 无所不可 |

**上电之特权是枢态，不是化态。** 此非随意：启机之第一令是 降化，
而 降化 是特权之令，化态行之便是越权。故必自枢态起，降而后入化——
此与真机之 reset 入管态同理。

又 太极 之中锁爻器之初态不可恃（`典/02` 第八戒），
故此处之特权亦**显式**置于枢态，不倚赖零值。

### 化态 之三禁

1. **取指不入枢之域。** 此检须在 步 **之前**——若待 L2 把那条令取进令器再查，
   化态便已见了枢之码，纵随即陷之，码亦泄矣。真机之中此检在地址总线上，
   取指之先；此处亦然。此陷不耗一拍，盖其拍未曾成。
2. **读与写不入枢之域。** 犯禁者**先撤其效，再陷**（§五·撤）。
3. **不行特权之令。** 降化 与 回 二者，化态行之则越权。

### 特权之漏，是最静的一种错

特权一旦漏出去，此后的每一次存取都不再受检，而机器**一声不响**。
变异四（降化 不忘其特权）与变异五（回 不忘其特权）专守此条——
其中「回 而忘降其权」最险，盖 回 之后用户程将以枢态跑下去，
所触者皆不受检，而人只见它**跑得好好的**。

## 五、爻变：三因与三槽

| 因 | 名 | 何时 |
|---|---|---|
| `越权之变` | 越权 | 化态触枢之域，或行特权之令 |
| `越令之变` | 越令 | 未定之码 |
| `越号之变` | 越号 | 叩号越出六十四 |

变之表三槽，一因一槽，一槽一条 跃——**表者，码也，非数也。**

### 撤

```go
if 旧特权 == 化态 && 是枢之域(址) {
    if 是存 { m.诸字 = 旧字 } else { m.诸器 = 旧器 }   // 撤其效
    k.陷(...)                                          // 而后陷
}
```

`旧器`/`旧字` 是 步 **之前**之快照。**越权之存取不当留痕**：
写了的字要抹回，读回的器要还原——那值是偷来的。

此即演示（戊）之所陈：

```
越权之写**已被撤**：藏[0o777000] = 0o40777200，仍是「跃 261760」
```

> **那涯不是靠「不许」守的，是靠「撤」守的。**
> 只「不许」而不撤，则越权之读已然得手，纵陷又有何益。

### 轰：一声而止

枢态 之变无可救者，**轰**而止其机。

其故：`陷` 之首事是「存计 ← 来处」，而 存计 **只有一个**。
化态 陷来，存计 记的是化之来处；枢态 若再陷，那个来处便被覆了——
回 将不知返于何所。此非设计之疏，而是「一个存计只记一处」之必然。

欲救之须有**变之栈**：陷 之时先压栈，回 之时再弹栈。那是 M7 化（进程）之事。
M5 之枢只有一个用户程，故**宁可止，不可错**。

「轰」者，一声而止；非崩溃，是**知止**。

## 六、叩：六十四号与那道唯一的门

```go
var 叩之簿 = [叩号数]string{
	0: "出",  // 出一字于串口。兑 = 欲出之字
	1: "言",  // 出一串。兑 = 首址，离 = 字数；返 兑 = 0
	2: "入",  // 入一字。返 兑 = 所入之字，无则零
	3: "息",  // 停机。兑 = 退出之码
}
```

余六十号未备，跃于同一处 `叩未备`，返 兑 = −1。

### 叩之簿 是唯一之真源

叩之表之六十四行由它生成，诸号之常量由 `叩号`（依名反查）得之。
若他日别处手抄一份「号 → 名」，那一份必朽——
**此病在本项目中已发五次**（`器号表`、`助记码表`、变异脚本之 `PAT`、测试之枢、
以及 `典/00` 之叩之约表——后者曾把 离 径列「可坏」，而 枢言之身 正是以 离 传字数），
故此处宁可绕一道反查，不肯再立一份。

> 第五次是收档改文档时发之：**码从未错过，错的是那张说码的表。**
> 表是手写的，码是生成的——手写的那份总会朽，这便是全部的理由。

### 行叩 之四部

```
一、还 M3 之债（m.止 = false）——须在分岔之前
二、校权（枢态 行叩则轰）
三、校号（越界则陷 越号之变）
四、记其来处（存计 ← 计），改其计与权（计 ← 叩之表基+号，特权 ← 枢态）
```

**「还债」何以前列**：债者，L2 之中 叩 与 停机 同置其 止
（M3 之 叩 只停机，别无他事），而 M5 之 叩 当陷阱，不当停机。

何以须在**分岔之前**：越号者亦是一条陷阱之路（陷 越号之变），
若待「号在界内」才抹其 止，则越号之叩便带着 L2 那个 止 一起陷进去——
**陷虽成，机已止，变之处理器遂一字不得行。**

它不报错，只是那一支**静静地不去**。故：**债要还，便还尽。**
变异十八专守此条。

### 计 之自增与返址

执行相之末 计 已自增，故此刻之 计 便是**次令之址**，正合返址之义。
若记了 叩 自己的址，`回` 便成死循环。变异十一专守此条。

## 七、器区：八口，是口不是址

| 口 | 名 | 读写 |
|---|---|---|
| 0 | 出 | 写之即出一字 |
| 1 | 志 | 读之非零则可出，恒为阳 |
| 2 | 入 | 读之得一字，无则阴 |
| 3–7 | — | 未配。读之得零，写之无物受之 |

器区居藏之极（`0o777770`），**是口，不是址**。

> 写器区**不入藏**。若写了也入藏，则器区便与寻常之址无异，唯多一重副作用而已。

二事值得一提：

- **写只读之口，无物受之。** 真机亦然（其写弃于总线），故此处亦不当报错。
- **读入坤器，无物受之。** 「坤恒为零」之约强于此——
  故「自器区读入坤器」是一句无物受之的读，器件之出遂弃。

出 与 入 皆以**字**为单位，一字便是一个汉字（§八）。

## 八、字之文：码位与三字节，与一处旧说之修正

> **典/01 云「一字三字节，正合一汉字之 UTF-8」。其言不虚，然其言未尽。**

```
UTF-8 三字节只容得 BMP 之内（十六位），U+FFFF 以外者一字节也放不下；
码位则不择——极于 U+10FFFF，需二十一位，而字有二十四位，绰有余。
```

故以**码位为正，三字节为其用之一端**：字里存码位，出时按 UTF-8 编码成字节流
付与串口（那是 出之流 的事，不是 字 的事）。

此亦 M4 以来一贯之实践——`译.go` 之 `字 '道'` 取 36947 而非三字节，
演示与测皆以 `rune(v)` 观之。**是实践先定了码位，而 典/01 之旧说未及追。**

字非字者（是条令、是个数、是个址），以码示之，不以乱码示人：
码位越界、落在代理区（U+D800–U+DFFF，本不成字）、或不可印者，
皆以 `⟨0o…⟩` 示之。

> 此病之发现，是输出成了 `⟨0o00073330⟩` 而人以为乱码——
> 实则 0o73330 = 0x76D8 = U+76D8 = 「盘」。**机器一直是对的，是显示错了。**
>
> 而 `Test字之文` 之所以杀得着变异廿四（字之文 只容 BMP），
> 是因为它验了 U+20000（𠀀）与 U+1F600（😀）——
> 那正是「码位之说」与「三字节之说」**分道之处**。
> 只验 BMP 之内者，此变异便活。**瞎处须另立一验。**

## 九、变异测试：廿五变异，廿五皆杀

> 对拍全绿，不等于处处验到。**验之疆界，须以变异测试量之。**（`典/08`）

`zsh 具/变异枢.sh`，约四分半。七道自检：

| 检 | 所防 |
|---|---|
| 〇、残留之检 | 上一趟若横死（SIGKILL），其遗毒当先清（§十） |
| 一、起手之检 | 当下之 枢.go 须是干净的，否则所量者全是错的 |
| 二、首之检 | 干净之 枢.go 全绿 |
| 三、验数之检 | 包内实有之验 与 实跑之验 当同（今 106） |
| 四、还原之检 | 每试之前先还原，收工之后校校验和 |
| 五、尾之检 | 还原之后仍全绿 |
| 六、自检 | 注入一个**无害**变异，此具**当报「存活」**——一个只会说「已杀」的器，它的沉默什么也不说明 |

```
【总账】共 25 变异：已杀 25，存活 0，可疑 0
        25 变异，25 皆杀——诸验之疆界，今已量至此处
```

### 一处瞎处：十三、轰 不置其止

初跑时**此变异存活**。其故是一桩标本级的瞎处。旧验有二：

```
Test枢态行叩则轰　　码是「叩 0 ⏎ 停机 0」
Test枢态之变则轰　　码是「字 未定之码」，而下一字是零，零即「停机 0」
```

两处之 轰 后面**都恰是一条停机**。机遂止了——
然那是 停机 止的，不是 轰 止的。`轰否` 犹真，`跑必止` 犹过，
而 轰 之「止」**一字未验**。

> 所验者（`轰否`，一志）与被坏者（`止`，一效）不是同一物，
> 而坏掉的那个效，恰好由别的东西补上了。
> **一个验法验不到的东西，跑一万遍也是验不到——它不报错，只是一遍遍地绿。**

治法不修旧验（它验 轰否 与 轰由 验得很好），而**另立一验** `Test轰则即止`：
令 轰 之后别无停机可撞，其后唯有一条死循环。
机若止，必是 轰 止的；机若不止，`跑` 必报「未止」。
**令那处再无物可补，则瞎处自明。**

### 一个死于编译、而非死于案的变异：廿一

变异廿一初版作「出之口 与 志之口 互易」，其果是 志之口 有二支，
**编译不过**。此具报「已杀」，然那不是案杀的，是**编译器**杀的。

> 一个靠编译不过而死的变异，什么也没验到：
> 它只证明「源码改坏了便编不过」，不证明「诸验分得出出与不出」。
> **编不过与「验到了」是两回事，而前者会把后者盖过去。**

故改为纯语义之变异：`append` 一行易作 `_ = 值`，编得过，而字已弃。
今 `Test器区之出`、`Test叩之出`、`Test开天之验` 三案皆杀之。

此具遂立「可疑」一数：编译不过或崩而死者计于此，不为零则须察。
**逐行点数易漏，故三数由 try_mut 自累加，收工一并报出。**

## 十、一桩真事：陷阱捕不得 SIGKILL

此具**尝被强杀**：退出码 137（= 128+9 = SIGKILL）。

自愈之陷阱（EXIT/INT/TERM/HUP/PIPE 皆设）**一个也没跑**——
SIGKILL 捕不得、拦不住、不作数，进程无声而去，一个字也来不及收。
`枢.go` 遂带着变异十一（`存计 = 计-1`）留在盘上。

> 此病最毒之处：**它不报错。** 八验皆红已是万幸——
> 若那变异恰好是「存活」的，则无人知晓，下一趟以带病之版为「原样」，诸果皆废。

故不靠陷阱，靠**遗书**：备份与标记皆改**固定名**（不掺 `$$`），
每注一变异先落标记，收工方删；起手时标记犹在，便知上趟横死，径自备份还原。

> 名随进程而变，则新的一趟**认不出上一趟的尸首**。

又：以 `nohup … &` 起之亦无效——`nohup` 只挡 SIGHUP，
挡不住进程组被强杀。须以工具原生之后台起之，进程方得存活。

## 十一、枢何以是码

> **枢 若用 Go 写成，则 M5 所成者不过是个「会跑叩的模拟器」，而非一台有内核的机器**——
> 叩 之服务例程是 Go 的函数，机器从头到尾没写过一行。

故枢**必须是码**：以译卦器之语写就，`汇` 之，装入高址，
由 L3 之陷阱跳进去，由它自己读写器区，再以 回 返回。

```
； ---- 叩之表：六十四槽，一槽一条 跃 令 ----
处 0o777000
跃 叩出
跃 叩言
⋮

； ---- 枢之正文 ----
叩言：
	加数 震, 兑, 0       ；暂乙 ← 首址
	载高 艮, 坤, 0o777
	加数 艮, 艮, 0       ；暂甲 ← 器基
言环：	等跃 坤, 离, 坤, 言末
	载字 兑, [震]        ；兑 ← 藏[暂乙]
	存字 兑, [艮]        ；出之口 ← 兑
	加数 震, 震, 1
	减数 离, 离, 1
	跃 言环
言末：	加数 兑, 坤, 0
	回 0
```

**本文件之中，凡数皆由常量算出，不由手书**：叩之表之六十四行由 叩之簿 生成，
诸叩之号由 叩号 反查得之，器基之二令由 器基 算出，化言之字数由 化之言 算出，
变之因之码由 变因 之值算出。此非炫技——**手抄之单必漏，
而漏在过滤器上者不报错，只是不见了**（M4 之训）。

### 一处令式之固然：置数

乙型之立即数是**十二位有符号**，界在 −2048..2047。
一个汉字之码位（如「盘」U+76D8 = 30424）便装它不下。

故凡欲置一大数者，皆须二分之：`载高` 置其高十二位，`加数` 补其差。
此非权宜，是令式之固然。差之取整向上而不向下——向下则余必在 0..4095，
而十二位有符号之上界是 2047，故余过 2047 者装不下（`器基` 之余正是 4088）。

**装不下便 panic。宁可炸，不可静默地算错一个数**——
一个算错的数不会报错，它只是把字写到别处去、或把别的字印出来。

## 十二、M5 之三戒

1. **抽线，不抄式。** 一拍之实尽委 L2；凡 L2 中已有的线，L3 一律委之，不另抄一式。
   抄一份，便有两处可独改而无声。
2. **由因出果，不由果抄果。** `是枢之域` 之界由 `化之极` 出，不由 `枢基` 出。
   二名虽同指一址，然一是因一是果。
3. **债要还，便还尽。** 还 M3 之债（`m.止 = false`）须在**分岔之前**——
   债只还了一半，等于没还；而那一半不报错，只是静静地不去。

（另有一条已入 `读我.md` 之七戒：**测试若另立一份枢，则所验者非所跑者。**
诸验一律呼 `建化之机`，换的只是 化之程 里那一段用户程。）

  待 M7 籍（文件系统）与化既立，方知当立何号。
- **虚境（分页）**：坤上之 `0o05`–`0o07` 与巽上（`0o30`–`0o37`）留此。
- **中断**：今只有**陷**（同步之变），尚无异步之中断。器区无「告」之口，
  故外设有事亦无从叩枢。M6 序（调度）之前须补。
- **特权之实现在 Go 的 if 里，不在电路里。** 此是模拟，不是实现——
  M5 不造电路，只造契约。契约既定，他日若要把枢刻进门里，
  `枢.go` 便是它的规约，而 `具/变异枢.sh` 便是它的验收。
