## 0. 定位与边界

**目标**：不是造一个能替代 Linux 的系统，而是从与非门出发，**自底向上重建一整套计算概念体系**，每一层的命名、编码、符号都出自中文与易学。最终产出是一台**自洽可运行的计算机 + 一个能跑的操作系统 + 一条完整工具链**。过程本身就是成果。

**四条不可逾越的事实边界**（已核实，决定了整个架构）：

| 事实 | 后果 |
|---|---|
| 逻辑门层只有 bit，八进制 = 3 bit 的天然分组 | 八进制**不需要"模拟"**，它与二进制无损对齐；八卦 = 3 bit 在数学上精确成立 |
| 卦符号（六十四卦 U+4DC0、八卦 U+2630、太玄 U+1D300）在 Unicode 属 **So 类**，不满足 XID_Start | **不能做标识符**（Rust/Go 都不行），只能做汇编助记符、字面量、输出。标识符必须用汉字（Lo 类） |
| **甲骨文未进 Unicode**：仅列于第三平面（TIP）路线图，2003/2011/2013/2015/2019 五次提案均未通过 | 甲骨文无法用于编码层；要强行使用只能占用私用区（U+E000 起），代价是字体、输入法、工具链全线断裂 |
| 《皇极经世》元会运世是 **12/30 进制**（1元=12会=30运=12世=30年） | 与二进制不可对齐，**只用于纪年/版本/时间显示层，禁止进内核数据结构** |

## 2. 机器规格：爻机（24 位）

**字长 24 位 = 8 卦 = 8 个八进制位**。选 24 位的三个理由：

1. 24 是 3 的整数倍，八进制/卦边界**永不撕裂**（16 位做不到，16÷3 无法整除）
2. **一个 24 位字 = 3 字节 = 正好一个 UTF-8 汉字**（基本区 U+4E00–U+FFFF 与六十四卦符号 U+4DC0 都是 3 字节）。按字寻址时，内存天然是"一字一汉字"
3. 地址空间 2²⁴ = 16 M 字 ≈ 6 MB，足够跑操作系统

**寄存器**：8 个，3 bit 编址，以八卦命名（乾兑离震巽坎艮坤）。

**指令格式**（三种，均 24 位）：

```
甲型（寄存器型）  [6b 卦·操作码][3b 乾兑…rd][3b rs1][3b rs2][9b 功能位]
乙型（立即数型）  [6b 卦·操作码][3b rd][3b rs1][12b 立即数]      ← 12b = 4 个八进制位
丙型（跳转型）    [6b 卦·操作码][18b 地址]                        ← 18b = 6 卦
```

**操作码空间**：64 条基础指令，用六十四卦（文王卦序 U+4DC0 起）一一对应。

**内存映射 I/O**：串口映射到固定地址，用于输出汉字（第一个可观测的产出就靠它）。

**系统调用**：单条指令「叩」，调用号置于乾寄存器，范围 `0o0`–`0o77`（64 个），按文王卦序命名。

## 3. 模拟器「演」：三档抽象

全部用 **Go** 实现（你最熟练，且并发/性能足够）。

| 档 | 粒度 | 用途 |
|---|---|---|
| L1 门级（爻级） | 逐门事件驱动求值，可见每一爻翻转 | 验证电路正确性，教学价值最高 |
| L2 周期级 | 以「辰」为单位求值模块 | CPU 数据通路验证 |
| L3 指令级 | 直接解释 24 位指令 | 跑内核与操作系统，追求速度 |

L1 与 L3 必须能**对同一程序给出一致结果**，这本身就是最强的正确性测试（交叉验证）。

> **关于 QEMU**：你选的"纯 QEMU 模拟"是在"复用现有 ISA"语境下的选择。既然改为从逻辑门自研，QEMU 不再作为目标机（理由见 §0）。QEMU/Linux 仍作为**开发宿主机**使用。若反对，请指出，可改回 RISC-V 助记层方案。

## 4. 里程碑（自底向上，每级都有可运行产出）

### M0 · 阴阳与门（约 1–2 周）
- **概念**：布尔代数、真值表、门电路、组合逻辑
- **产出**：Go 写的 L1 门级模拟器内核；用「与非门」派生出 与/或/非/异或/多路选择器/译码器
- **验收**：16 位（=2 卦+…）与门的穷举真值表全通过；能画出电路网表并求值

### M1 · 四象算术（约 1–2 周）
- **概念**：补码、加法、溢出、ALU
- **产出**：半加器 → 全加器 → 24 位算爻器（加/减/与/或/异或/移位/比较）
- **验收**：全部运算与 Go 原生结果对拍通过；负数用「阳阴互易」的规则表达（呼应平衡三进制的取反思想）

### M2 · 八卦时序（约 2 周）
- **概念**：反馈、状态、时钟、存储
- **产出**：锁爻器（D 触发器）→ 卦器堆（8 个 24 位寄存器）→ 藏（RAM）→ 辰（时钟）→ 程序计数器
- **验收**：能写入并读回内存；寄存器堆在辰的驱动下正确翻转

### M3 · 六十四卦指令集与太极（约 3–4 周）—— **已成（2026-09-01）**
- **概念**：取指—译码—执行循环、冯·诺依曼结构
- **产出**：定下完整 ISA 规范；用 M0–M2 的部件搭出数据通路与控制单元；L2 周期级模拟器
- **验收**：跑通一段手写的 24 位机器码（如计算斐波那契），L1 与 L2 结果一致
- **实成**：
  - `令.go` ISA 之契约（十七令 + 算爻十六令；三型；上卦定类、下卦定操）
  - `太极.go` 演 L1 门级，33 756 门 / 33 790 线（藏 32 字）
  - `周期.go` 演 L2 周期级，一拍 17 ns，快 L1 约十九万倍
  - `程.go` 手编之机器码（斐波那契、累加之属）
  - **验收已达**：斐波那契十一字，L1 **132 拍得 离 = 55 = fib(10)**；
    L1 与 L2 **逐拍对拍，十三案 324 拍处处相合**，又经十三变异之验
  - 全案见 `典/08-太极运化.md`

### M4 · 译卦器（汇编器与反汇编器）（约 2–3 周）—— **已成（2026-09-02）**
- **概念**：符号、地址、标签、重定位
- **产出**：Go 写的汇编器——源码用汉字助记符（如 `载 乾, [地址]`）与卦符号（䷀ 等）书写，输出 24 位机器码；配套反汇编器
- **验收**：round-trip 测试（汇编 → 机器码 → 反汇编 → 文本一致）
- **实成**：
  - `译.go` 译卦器：词法、译数、三型之译、伪令二（`处` 定址、`字` 置数据）、
    `汇`（两遍之译）／`汇一`、`令之译`／`反汇`
  - **双向之约**：`令名`／`助记码表`／`器号表` 三表皆由 `取型`/`分类`/`卦名` 推出，
    不由手抄。增一令，两侧同时长出
  - **验收已达**：`汇一(令之译(令)) ≡ 令`——**全域穷举 7 026 365 字，无一不合**；
    又 `汇(反汇之文(诸令)) ≡ 诸令`
  - 与 M3 手编之码**逐字相合**（斐波那契 11 字、存取 7 字、累加 6 字）；
    译出之码跑之 **132 拍得 离 = 55**，与手编者一拍不差
  - **十六变异，十六皆杀**；中途存活之三，各挖出一处盲区
  - 全案见 `典/09-译卦器.md`

### M5 · 枢（内核）与叩（系统调用）（约 4–6 周）—— **已成（2026-09-03）**
- **概念**：特权级、陷阱、ABI、中断
- **产出**：L3 指令级模拟器；内核「枢」：初始化、异常向量表、叩分派表（64 个，按卦序命名）、串口输出
- **验收**：用户态程序执行「叩」，内核接管并通过串口打印汉字。**这是第一个"操作系统"闭环**
- **实成**：
  - `枢.go` 演 L3 指令级枢机：特权（化态／枢态）、爻变（越权／越令／越号）、器区（八口）
  - `枢程.go` **枢是码**：以译卦器之语自陈，`汇` 之而装入高址；
    Go 那一侧只做机器本该由电路做的三件事，一字节的内核逻辑也不在 Go 里
  - `令.go` 增 降化（0o03 ䷭ 升）与 回（0o04 ䷗ 复），皆丙型、皆特权
  - **L3 之可信由两事证之**（其上再无 L4 可对其拍）：
    一、**抽线不抄式**——L2↔L3 逐拍对拍，五段程 **884 拍**处处相合；
    二、**量其新逻辑**——`具/变异枢.sh` **廿五变异，廿五皆杀**，七道自检
  - **验收已达**：`Test开天之验` **94 拍**，启 之 降化 → 叩「言」→ 五次 出 → 回 → 叩「息」，
    **出「盘古开天！」**——那五个字是码打出来的
  - 全案见 `典/10-枢与叩.md`

### M6 · 化与序（进程与调度）（约 4–6 周）
- **产出**：进程控制块（称「化块」）、上下文切换、时间片轮转调度（称「序」）、虚境（分页，每页用卦编址）
- **验收**：两个「化」交替运行，各自的内存互不干扰

### M7 · 籍与目（文件系统与中文 shell）（约 4–6 周）
- **产出**：内存文件系统，节点称「节」；shell 命令用单双字（列/读/写/删/运行）
- **验收**：能创建、读写、列举文件；文件名是 UTF-8 汉字

### M8（可选）· 译经器（高级语言）
- 自研一门中文语法的系统级语言，编译到 M4 汇编层。参考 wenyan-lang（图灵完备，已有「爻」布尔类型，值为阴/阳），但它面向宿主语言、不适合裸机

## 6. 技术选型与放弃项

| 选型 | 决定 | 理由 |
|---|---|---|
| 实现语言 | **Go** | 你最熟悉；模拟器/汇编器/编译器都够用；开发速度最快 |
| 目标 ISA | **自研 24 位** | 用户明确要求从逻辑门起；且 24 位与 UTF-8 汉字天然对齐 |
| QEMU | **放弃作为目标机** | 无法为新 ISA 加 target；自研模拟器替代 |
| Rust 中文标识符内核 | **放弃** | 无现成 ISA 可编译（见 §0 说明，此条由"从逻辑门起步"推出） |
| 甲骨文编码 | **放弃**，仅作 Logo/文档装饰 | 未进 Unicode，私用区造字会摧毁全部工具链互操作性 |
| 元会运世 | **仅用于纪年/版本显示层** | 12/30 进制与二进制不可对齐 |

## 7. 风险清单

**会致死项目**：
1. **自研 ISA 导致工具链真空** —— 没有调试器、没有 profiler。缓解：M4 就自写反汇编器；L3 模拟器内置单步/断点/转储，从第一天就把它当调试器设计
2. **门级模拟器太慢跑不动 OS** —— 缓解：三档抽象，L1 只验证电路，跑系统一律走 L3
3. **范围蔓延，M0–M7 全部半途** —— 缓解：严格串行推进，每级产出可运行成果才进下一级

**会让项目变慢**：
4. **卦符号字形缺失**（U+4DC0 在多数等宽字体中无字形）—— 缓解：固定 Sarasa Mono / Noto Sans Symbols 2 / BabelStone Han；工具链保留 ASCII 回退模式
5. **中文标识符输入慢** —— 缓解：编辑器 snippet + 短标识符 + AI 补全
6. **UTF-8 三字节膨胀** —— 缓解：内核日志内部存编号，用户态查表翻译成中文
7. **NFC 同字异码** —— 缓解：pre-commit 强制 NFC 规范化

## 8. 第一个动作

创建 `盘古/演/` 的门级模拟器骨架（约 200 行 Go）：定义 `爻`（bool）、`门` 接口、`网表` 结构与事件驱动求值循环，然后用与非门派生出与门、或门、非门，跑通穷举真值表测试。

这一步约 1–2 周，产出是整个体系的地基，也是验证"这条路走得通"的最便宜的方式。
