## 二、籍区之址：籍基 居 枢基 之下，而 化之极 由 籍基 出

```
0o000000 ┌──────────────┐
         │  化之域       │  化态之所能触者，0 .. 化之极-1
         │              │  每一化另有其界（界基 ＋ 虚址，虚址 < 界限）
0o776000 ├──────────────┤ ← 籍基 ＝ 化之极
         │  节表         │  节数 × 节之度 ＝ 0o400（二百五十六字）
         │  籍存         │  核之暂名之区（比名时用）
         │  （余）       │  留与后之里程：目录之树、块之位图
0o777000 ├──────────────┤ ← 枢基
         │  叩之表       │  六十四槽
         │  变之表       │  五槽
         │  枢文         │  叩之服务与变之处理器；**籍之码亦在于此**
0o777700 ├──────────────┤ ← 器基
         │  器区         │  非藏，写之无所存
0o777777 └──────────────┘
```

### 化之极 是「果」，籍基 是「因」

M6 之时，枢之域只有枢一部，故 `化之极 = 枢基` —— 二名虽异，其实一址。
M7 立籍区，枢之域遂有籍与枢二部；而 **化之极 之义不变**：
它是「化态之所能触者止于何所」。

```
化之极 = 籍基     // 旧：= 枢基
```

若仍书 枢基，则籍区遂成化态可触之地，而一化便写得动别化之档——
**那正是 M6 花了整整一个里程碑去堵的那个洞**。
而这一处不会报错，只是籍区安安静静地开着门。

> 二名同指一址时，抄哪一个都「能跑」。
> 抄**果**的那一处，在因变的那一天静悄悄地失效；
> 抄**因**的那一处，则永远跟着因走。
> 此是**由果抄果之第三发**（前二发：M5 之 `是枢之域`、M6 之此界），详见 §八。

### 枢文基 由 变之表 出：把白弃的 59 字捡回来

```
枢文基 = 变之表基 + 变之数    // 旧：= 枢基 + 0o200
```

旧作 `枢基 + 0o200`，而 变之表 只占五字，其间 0o73（五十九字）遂白弃。
M7 之籍须以码为之，枢文骤长，那五十九字便是从隙里捡回来的——
**枢文之余地 320 字增至 379 字**，籍之码装得下。

址既由 变之表基 与 变之数 算出，则表若长，正文自随，
不须有人记得去改 0o200 这个数。

而「枢文装得下装不下」，旧以临时探针量之，量毕即删。
今立 `Test枢文不侵器基` 为**常驻之量具**：枢之码不得长过器基，
且**余地不足二十字者亦红——先红于此，胜于红于彼**。

## 三、一节之形

```
一节（三十二字）
  0o00 ┌──────────────┐
       │ 名            │  0o10 字，末以零终 ⇒ 名之极 七字
  0o10 ├──────────────┤
       │ 长            │  据之字数
  0o11 ├──────────────┤
       │ 志            │  零则未用，非零则在用
  0o12 ├──────────────┤
       │ 据            │  0o26（二十二）字，正文
  0o40 └──────────────┘
```

```
节之度 = 0o40
节之移 = 5             // 节之度 ＝ 1 << 节之移
节数   = 0o10          // 八节
节表之量 = 节数 * 节之度 = 0o400
节址   = 籍基 + (号 << 节之移)
```

### 名之有尽，在其字中，不在其旁

何以名以零终而不另记其长：若另记名长，则名有二处可改（字与长），
改其一而另一朽；以零终之，则比名之时比到两零而自止，长无用矣。

**长 只记 据 之字数**，不记 名 之字数——名不须记。

### 节址 以移位得之，不以乘

三十三是二之五次方吗？不是；**三十二才是**（0o40 = 32 = 2⁵）。
故 节址 ＝ 籍基 ＋（号 << 5），五次移位即可。

机器无乘器（M1 之八操亦无乘），凡能以移位代乘者，皆当以移位为之——
此非取巧，是机器之固然。

而 `节之移` 这个数**由 节之度 算出则不能**（Go 之常量无对数），
故立此名而验之：`Test籍之度与移相合` 专守「1 << 节之移 ＝ 节之度」。
**名可手书，验不可无**——手书之数若无处验，它便是下一个人的坑。

## 四、籍之六叩

| 号 | 名 | 兑（元一） | 离（元二） | 坎（元三） | 返（兑） |
|---|---|---|---|---|---|
| 4 | 建 | 名之首址 | 名字数 | — | 节号，重名或籍满则 −1 |
| 5 | 求 | 名之首址 | 名字数 | — | 节号，无则 −1 |
| 6 | 写 | 节号 | 源址 | 字数 | 实写之字数 |
| 7 | 读 | 节号 | 目址 | 字数 | 实读之字数 |
| 8 | 删 | 节号 | — | — | 零，无此档则 −1 |
| 9 | 目 | 节号 | 目址 | — | 名字数，无此档则 −1 |

号 与 名 皆自 `叩之簿` 出（唯一之真源）；叩之表 之六十四行由它生成，
演示之表亦由它生成，不手书（M4 之训：凡手抄之单，必漏）。

### 与其验其址，不如不与之址

六叩**皆以节号为凭，不以节址为凭**。

节址 是枢之址。它若落回化态之手，化 遂持一柄枢门的钥匙——
枢 还得验它是不是真的，而**验得再严，也强不过不给**。

号 则不然：号 越界者，枢 一较便知（号 < 节数），
而化态纵持一个荒唐之号，也指不到任何一个址。

这是 M5「抽线，不抄式」之外的另一条路：
**不是把验写得更好，是把「须验的东西」取消掉。**

### 志 是诺，诺在其实之后

`建` 之序：先查重名、再寻空节、录其名、**末了方置 志 ← 1**。

若先置志而后录名，则此节在建成的半途上已是「在用」——
此时若有另一化求之，它求得一个名犹未录全的节。
**诺在其实之先，则诺是谎。**

### 删 只置 志 ← 0，不抹其文

删 之后，名与据犹在演示【九】（己）之表中可见。
抹了又建，是白跑一趟；而**留着，则「删」是一记 O(1) 的写**。

此与真文件系统之 `unlink` 同理，而此处更简：
无链接之计数，无块之回收——志 之一字，便是一档之生死。

## 五、名之比：籍存

比名之环须二游标（节名、用户名）与二暂存之字（各一字），凡四器；
而八器之中，坤为零、乾为叩号，止余六器，犹须留一器以记余下之节数。
四加一得五，六器足矣——
**然用户名之游标每历一节便须归其原处，而归处之址已无处可记。**

故核先以界基引用户之名入 `籍存`（其址是常数，随时可置），
然后与诸节比。**先移进来，则归处不必记。**

若他日籍有目录之树，此暂存当不止一处；今只一名，故只一区。

## 六、壳：第一个用 叩 说话的程

**壳 亦是一「化」**——它行不得特权之令，触不到枢之域，
所能者唯 叩 而已，与诸用户之程分毫无别。

> **壳之尊，不在其权，在其为第一个用 叩 说话的程。**

### 六令

`列` `建` `写` `读` `删` `止`，报以三色：`成` `否` `无`。
不识之令报「否」而不轰、不死——
**壳 不当因一行之无稽而死**；真壳遇不识之令，报一声错便是。

### 写 读 删 先 求 其号而后叩

壳 若自算节址，则「与其验其址，不如不与之址」遂破于壳之手——
故 壳 手上只有**号**，而号是枢给的。

### 两端之取舍

- **换行何以是「⏎」而非 U+000A**：字之文 于不可印者皆作「⟨0o…⟩」，
  出一个 U+000A 便印出 `⟨0o000012⟩` 来——**能出而不能读，与不出同**。
- **游标何以在藏而不在器**：叩之约，叩 可坏 艮坎巽震离；
  化态之器过不得一次叩。分元之内虽无叩，然**出入同处**，
  则不须记「哪一个游标在器里」——**而须记住的事，迟早会忘**。
- **码 192 字，数区 92 字，余地 256 字**（`Test壳之区不侵其码` 守之）。

## 七、M7 之诸验

十五验在籍，七验在壳，一验量枢文。其要者：

| 验 | 所守 |
|---|---|
| `Test籍之度与移相合` | 1 << 节之移 ＝ 节之度。不合则诸节之址相叠，而 建、求 **皆不报错** |
| `Test籍之建求往返` | 建 而后 求，同名者当得同号 |
| `Test籍之籍满则负` | 第九节当建不成。杀「升之移 只移一位」者，**是此验，不是往返之验** |
| `Test籍之重名则负` | 同名不二建 |
| `Test籍之越址则负` | 三检：址 < 0、址 ≥ 界限、余 < 字数 |
| `Test籍之规范式` | 长 与 志 之形 |
| `Test化态不得径入籍区` | 化态 径写 籍基 则陷，且**藏一字未改** |
| `Test枢文不侵器基` | 枢之码不得长过器基；余地不足二十字亦红 |
| `Test壳之全程` | 九令九报，逐字核之。**此是 M7 之验收** |
| `Test壳之区不侵其码` | 码之末（壳码之末 这一签）不得侵入数区 |

### 量具够不着的地方，须另立一具

`Test籍之越址则负` 原有三案，然「余 < 字数」这一检**从未被举**：
前此诸案皆被「址 ≥ 界限」抢先。故增二案，皆是为变异而立：

- **「界内而字数越其末」**（址 ＝ 界 − 1，字数 ＝ 2）：三检之中，独此一举。
- **「负址」**（址 ＝ −1）：界之比从符号，故 −1 者另二检皆不举。

一个验法验不到的东西，跑一万遍也是验不到——
**它不报错，只是一遍遍地绿**。

## 八、变异测试

五十六式，**五十六皆杀**，存活 0，可疑 0。八道自检皆过
（残留、起手、首、验数、还原、尾、自检、汉字之名、换手）。

M7 新拓之十一式（四十六至五十六）与其所死之验：

```
四十六：升之移 移一位        Test壳之籍满则否
四十七：降之移 移一位        Test籍之籍满则负
四十八：比名 不略废节        Test籍之建求往返（共 4 验红）
四十九：检址 不检址之下界    Test籍之越址则负
五十：检址 不检余之不足      Test籍之越址则负
五十一：裁数 不裁            Test籍之写越据则裁
五十二：检数 不检字数之极    Test籍名过其极则负
五十三：删 不置其志          Test籍之删而复建（共 3 验红）
五十四：节址 不检号之下界    Test籍之写读往返（共 8 验红）
五十五：壳 不以无字为止      Test壳入尽则自息
五十六：分元 空格之判倒      Test壳之全程（共 3 验红）
```

### 一处真病：一具之病，使其后诸式皆「已杀」（首趟之账大半是假的）

首趟跑毕，账是「五十四杀、一存活、一未注入」，
而**四十六至五十六式无一不报同一个杀手 `Test器口之簿`**。
一式杀一验，十一式杀同一验，那便不是巧合，是病。

手动注入四十六式验之：**红的只有 `Test壳之籍满则否`**，并无 器口之簿。

其故：`用` 换手时只改 `SRC`，而 `try_mut` 之 `restore` 还原的是**新的** SRC。
故第四十五式（器口之数 不由簿出）之病一直留在 `枢.go` 上，
陪 `枢程.go` 的十一式跑完了一整程。那病已足以使 `Test器口之簿` 恒红，
而 `who` 取 `head -1`，遂把真凶盖在下面。

**那十一个「已杀」、那「存活 0／可疑 0」，看起来是全项目最漂亮的一张账，
而它一个字也不可信**——纵四十六至五十六一式也没有，
四十五 那一份病也足以使诸验皆红。

治法二：

1. **换手之检**：`用` 换手之际，先还原旧主并校其校验和，不合则止。
2. **报「共几验红」**：一式若红了三十验，所报之 `who` 只是诸红之首，
   不是唯一的红者。报出其数，则「精准」与「大锤」一望而知。

> **一具之病，使其后诸式皆「已杀」，则那些「已杀」一个也不是真的。**

尤可自警者：换手处之注早写了「换手之时，前一文件犹带其上一变异」，
而其时只引以为「校验和只记一次」之由——
**看见了症状，却拿它去佐证另一件事**，未再追问一句「那它会不会污染下一程」。
注里写的机制，须与跑出来的相符（第十二戒），此是其**第四发**。

### 一处真病：由果抄果，第三发

`Test化态取指于枢之域则越权` 尝书：

```go
k := 建验机(t, "\t跃 0o777000\n\t停机 0\n")
```

其时 `化之极 = 枢基 = 0o777000`，故 0o777000 正是界外之**第一字**，
变异卅五（是化之域「址 < 界限」→「址 < 界限 ＋ 1」）遂死于此。

及 M7 立籍区，化之极 由 枢基 移就 籍基，0o777000 遂成界外**很远**之字——
**远则差一量不出**，而此验**仍然全绿**：它绿它的，变异活它的。
M7 首趟变异跑毕，卅五 由「已杀」变为「存活」，其故在此。

治法：跃向 **化之极**——界外第一字之**因**。

```go
k := 建验机(t, fmt.Sprintf("\t跃 0o%06o\n\t停机 0\n", 化之极))
```

化之极 一动，此验自随，不必有人记着来改。

> 一个验杀过一个变异，**不等于它永远杀得着**。
> 验之疆界系于它所书的那些常数；常数若是抄来的，疆界便随抄处而移。

### 一处真病：升、降 只移一爻

`升`、`降` **恒移一爻，不用立即数之域**（`令.go` 之注）。
书 `升数 兑, 兑, 5` 者，译卦器不报错，机器亦不报错，只算出个 `兑 << 1`。

杀它的是 `Test籍之籍满则负`，**不是** `Test籍之建求往返`——
后者之所以绿，是 号 ＝ 0 掩住了它：**0 移多少位皆 0**。瞎处。

治法：立 `升之移`／`降之移` 二器，欲移五位便书五条。

### 一处真病：检之三器（一个恒真的断言）

检址 原是一器 `籍之检址`，「字数之极」既是门槛又是字数。其病有二：

1. 写 27 字于容 22 字之节，**先检而后裁**，故未及裁便以「越极」论误——
   短写是半个答案，胜过一个「不」字。
2. `目` 之字数本就是 名之极，**「极 < 字数」遂恒假**。
   **一个恒真的断言与没有断言同。**

今析为三器：

| 器 | 所为 | 用于 |
|---|---|---|
| `检数` | 字数越极则**拒** | 名（名不可截，截则成他名） |
| `裁数` | 字数越极则**裁** | 文（文可截） |
| `检址` | 址与字数在现化之界内否 | 一切用户之址 |

**名不可截，截则成他名；文可截，短写是半个答案，胜过一个「不」字。**

### 又一处真病：式是会朽的

变异三（化之极 差一）之式原作 `化之极 = 枢基`，源既改就 籍基，
式遂不合而报「变异未注入」——**未注入不等于已杀**，此具对之另标「疑」。

式随源码而朽，则式亦当随源码而改；改式易，忘改难，故记于式旁：

```
# **式是会朽的**：此式原作 `化之极 = 枢基`…
# 式既随源码而朽，则式亦当随源码而改；改式易，忘改难，故记于此。
```

## 九、M7 之三戒

### 一、与其验其址，不如不与之址

一个值若是危险的，最省事的屏不是把它验好，是**不把它交出去**。
六叩以号为凭，即是此戒。

推而广之：凡见一处「验得很严」的代码，先问一句
**这个东西非给不可吗**。

### 二、名之有尽，在其字中，不在其旁

一件事若有两个地方记着它，其中一处必朽。
名以零终，则长不必记——**最好的同步，是不必同步**。

### 三、量具之疆界系于它所书的常数

`Test化态取指于枢之域则越权` 书「跃 枢基」而非「跃 化之极」，
遂在 化之极 移位的那天静悄悄地瞎了，而它自己**一直绿着**。

凡验之中有常数，须问：这个数是**因**，还是**果**？
是果者，改从因出。

- **虚境（分页）**：推至 M8。今籍之节表直接寻址，尚无须以页承之；
